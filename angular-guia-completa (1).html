▸ Piezas fundamentales
🧩
Component
Bloque básico de UI. Combina template HTML, estilos CSS y lógica TypeScript. Cada vista es un componente.
📦
Module / Standalone
Antes: NgModules agrupaban componentes. Ahora: standalone components sin módulos. Más simple y tree-shakeable.
⚙️
Service
Lógica de negocio y acceso a datos. Se inyectan vía DI. Reutilizables y testeables de forma aislada.
🔀
Router
Navegación entre vistas SPA. Lazy loading de rutas, guards de acceso, resolvers de datos y nested routes.
📡
RxJS / Signals
Reactividad. RxJS con Observables para streams async. Signals (v16+) para reactividad granular sin suscripciones.
🔧
Angular CLI
Herramienta de línea de comandos. Crea proyectos, genera componentes, compila, testea y despliega.
Los componentes son la unidad fundamental de Angular. Todo lo que ve el usuario es un componente, y los componentes se componen entre sí formando un árbol.
Componente clásico (NgModule)
// user-list.component.ts
@Component({
  selector: 'app-user-list',
  templateUrl: './user-list.component.html',
  styleUrls: ['./user-list.component.css']
})
export class UserListComponent
    implements OnInit {

  users: User[] = [];

  constructor(
    private userService: UserService
  ) {}

  ngOnInit(): void {
    this.userService.getAll()
      .subscribe(u => this.users = u);
  }
}

// Requiere declarar en un NgModule
@NgModule({
  declarations: [UserListComponent],
  imports: [CommonModule]
})
Standalone Component (v15+)
// user-list.component.ts
@Component({
  selector: 'app-user-list',
  standalone: true,
  imports: [CommonModule],
  template: `
    <h2>Usuarios</h2>
    @for (user of users(); track user.id) {
      <div>{{ user.name }}</div>
    }
  `
})
export class UserListComponent {
  private userService = inject(UserService);

  // Signal: reactividad granular
  users = signal<User[]>([]);

  constructor() {
    this.userService.getAll()
      .subscribe(u => this.users.set(u));
  }
}
// ¡Sin NgModule! Se importa directamente

Cada componente Angular pasa por un ciclo de vida controlado. Estos hooks permiten ejecutar lógica en momentos precisos: creación, cambios, destrucción.
Hook
¿Cuándo se ejecuta?
ngOnChanges
Cuando un @Input() cambia de valor. Recibe un SimpleChanges con el valor anterior y actual. Se ejecuta antes de ngOnInit. Inputs
ngOnInit
Una sola vez tras la primera ejecución de ngOnChanges. Ideal para cargar datos, suscribirse a observables y lógica de inicialización. ★ Más usado
ngDoCheck
En cada ciclo de detección de cambios. Permite lógica personalizada de detección. Úsalo con cuidado: se ejecuta muy frecuentemente. Precaución
ngAfterContentInit
Una vez, tras proyectar contenido externo (<ng-content>) en el componente. Content projection
ngAfterContentChecked
Tras cada verificación del contenido proyectado. Content projection
ngAfterViewInit
Una vez, cuando la vista del componente y sus hijos están inicializados. Ideal para acceder a @ViewChild. DOM ready
ngAfterViewChecked
Tras cada verificación de la vista. Se ejecuta frecuentemente. Precaución
ngOnDestroy
Justo antes de destruir el componente. Desuscribirse de observables, limpiar timers, liberar recursos. ★ Crítico
▸ Ejemplo de ciclo de vida
@Component({ selector: 'app-user-detail', ... })
export class UserDetailComponent
    implements OnInit, OnDestroy {

  @Input() userId!: string;
  private destroy$ = new Subject<void>();
  user: User | null = null;

  constructor(private userService: UserService) {}

  ngOnInit(): void {
    // Cargar datos al inicializar
    this.userService.getById(this.userId)
      .pipe(takeUntil(this.destroy$))
      .subscribe(u => this.user = u);
  }

  ngOnDestroy(): void {
    // Limpiar suscripciones para evitar memory leaks
    this.destroy$.next();
    this.destroy$.complete();
  }
}
▸ Change Detection
Default Strategy
▸
Angular revisa todo el árbol de componentes en cada evento
▸
Cualquier click, timer, HTTP response dispara una revisión completa
▸
Simple pero costoso en apps grandes con muchos componentes
OnPush Strategy
▸
Solo re-renderiza si cambian las referencias de @Input
▸
Requiere inmutabilidad y uso de async pipe u Observables
▸
Mucho más eficiente — recomendado en producción Recomendado

▸ Angular 12 — Mayo 2021
Angular 12 marcó la transición hacia Ivy como motor por defecto y eliminó el soporte para el antiguo View Engine. El paso hacia un Angular más moderno y eficiente.
Novedades clave
▸ View Engine deprecado — Ivy es el único motor de renderizado
▸ Nullish coalescing (??) en templates
▸ Soporte para Webpack 5 por defecto
▸ Strict mode activado por defecto en ng new
▸ Migración de TSLint a ESLint
▸ Sass migrado de node-sass a sass (Dart Sass)
Código ejemplo v12
// Template con ?? (nullish coalescing)
<p>{{ user.name ?? 'Anónimo' }}</p>

// Inline styles con Sass

  styles: [`
    :host { display: block; }
    .card { @include elevation(2); }
  `]
})
▸ Angular 13 — Noviembre 2021
Angular 13 eliminó por completo View Engine y mejoró el rendimiento del compilador Ivy. Se simplificó la creación de componentes dinámicos.
Novedades clave
▸ View Engine eliminado completamente
▸ Componentes dinámicos sin ComponentFactoryResolver
▸ IE11 eliminado — permite APIs modernas del navegador
▸ Mejoras en TestBed: teardown automático de módulos
▸ Angular CLI usando persistent build cache
▸ RxJS 7 por defecto

▸ Angular 16 — Mayo 2023
Angular 16 introdujo Signals (developer preview), el cambio más grande en el modelo de reactividad de Angular desde su creación. También trajo SSR mejorado y esbuild experimental.
Novedades clave
▸ Signals (developer preview) — reactividad granular sin Zone.js
▸ signal(), computed(), effect() — primitivas reactivas
▸ RxJS interop: toSignal() y toObservable()
▸ Server-Side Rendering con non-destructive hydration
▸ esbuild dev server (experimental) — builds ultrarrápidos
▸ Required inputs con @Input({ required: true })
Signals — El gran cambio
import { signal, computed, effect }
  from '@angular/core';

export class CartComponent {
  // Signal: valor reactivo
  count = signal(0);
  price = signal(29.99);

  // Computed: derivado automáticamente
  total = computed(() =>
    this.count() * this.price()
  );

  // Effect: side-effect reactivo
  log = effect(() =>
    console.log(`Total: ${this.total()}`)
  );

  add() {
    this.count.update(c => c + 1);
  }
}
▸ Angular 17 — Noviembre 2023
Angular 17 fue el release más grande en años. Nuevo branding, nueva web, nuevo built-in control flow (@if, @for), deferrable views y esbuild como default. Angular renació.
Novedades clave
▸ Nuevo built-in control flow: @if, @for, @switch, @empty
▸ Deferrable views: @defer con lazy loading declarativo
▸ Signals estabilizados: signal(), computed(), effect()
▸ esbuild + Vite como build system por defecto
▸ SSR hydration estable y habilitada por defecto
▸ Nuevo logo, nueva web angular.dev, nuevo branding
▸ Hasta 87% más rápido en builds con esbuild
Nuevo control flow + @defer
<!-- Nuevo @if (reemplaza *ngIf) -->
@if (user()) {
  <h2>{{ user().name }}</h2>
} @else {
  <p>Cargando...</p>
}

<!-- @for con track obligatorio -->
@for (item of items(); track item.id) {
  <app-card [data]="item" />
} @empty {
  <p>No hay resultados</p>
}

<!-- @defer: lazy loading declarativo -->
@defer (on viewport) {
  <app-heavy-chart />
} @loading {
  <div>Cargando gráfico...</div>
} @placeholder {
  <div>Scroll para ver</div>
}
▸ Angular 18 — Mayo 2024
Angular 18 continuó madurando Signals con signal-based inputs, outputs y queries. Introdujo zoneless change detection experimental y mejoras en SSR.
Novedades clave
▸ Zoneless change detection (experimental): sin Zone.js
▸ Signal inputs estables: input(), input.required()
▸ Signal queries: viewChild(), contentChildren()
▸ output() function para emitir eventos
▸ @let para variables locales en templates
▸ Fallback content para <ng-content>
▸ Material 3 como theme por defecto en Angular Material
Signal inputs & outputs
// v18: Signal-based inputs y outputs
@Component({ ... })
export class UserCard {
  // Signal input (reemplaza @Input)
  name = input.required<string>();
  age = input(18); // con default

  // Output function (reemplaza @Output)
  selected = output<string>();

  // Signal query (reemplaza @ViewChild)
  avatar = viewChild<ElementRef>('avatar');

  // Computed derivado de inputs
  greeting = computed(() =>
    `Hola ${this.name()}, ${this.age()} años`
  );

  onClick() {
    this.selected.emit(this.name());
  }
}
▸ Angular 19 — Noviembre 2024
Angular 19 consolida la era de los Signals con inputs, outputs y queries estables, avanza hacia un Angular sin Zone.js y mejora drásticamente el SSR con incremental hydration.
Novedades clave
▸ Standalone es el default total: ng new ya no genera módulos
▸ Incremental hydration: solo hidrata los componentes visibles
▸ Route-level render mode: SSR, SSG o CSR por ruta
▸ linkedSignal(): signals derivados con write-back
▸ resource(): primitiva para datos async reactivos
▸ Zoneless change detection en developer preview
▸ @let estable en templates
▸ Mejoras en HMR (Hot Module Replacement) para estilos
resource() y linkedSignal()
// resource(): datos async reactivos
export class UserPage {
  userId = input.required<string>();

  // Se re-ejecuta cuando userId cambia
  user = resource({
    request: () => this.userId(),
    loader: async ({ request: id }) => {
      const res = await
        fetch(`/api/users/${id}`);
      return res.json();
    }
  });
}

// linkedSignal(): writable derived
options = signal(['A','B','C']);
selected = linkedSignal(() =>
  this.options()[0]
);
// selected se resetea si options cambia
// pero se puede escribir manualmente

Conclusión

Angular ha evolucionado radicalmente desde la v12. La eliminación de NgModules obligatorios, la llegada de Signals, el nuevo control flow @if/@for, y el camino hacia zoneless han transformado la experiencia de desarrollo. Si vienes de versiones antiguas, el Angular actual es un framework mucho más simple, rápido y expresivo. La recomendación: adopta standalone + signals + nuevo control flow y disfruta del Angular moderno.
