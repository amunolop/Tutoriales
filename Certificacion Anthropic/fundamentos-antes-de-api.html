RUTA DE ENTRADA — 5 PASOS ANTES DE CCDV-F
Cuatro pasos de entrada (~11.5h en total, repartibles a tu ritmo) y un quinto paso donde ya entras de lleno en la formación específica del examen.
Claude 101 (2.5h)
Sin código. Vocabulario base: qué es un mensaje, qué es el system prompt, cómo se estructura una conversación. Ve rápido — mucho ya lo intuyes por tu experiencia con Claude Code.
Claude Platform 101 (1.5h)
Primer contacto formal con la API, la Console y MCP a nivel introductorio. Aquí empiezas a ver los nombres exactos (messages, system, tools) que hasta ahora Claude Code te resolvía por detrás.
AI Capabilities and Limitations (3.5h)
Cómo funciona un LLM de verdad: predicción de token, memoria de trabajo, límites de contexto. Es la base que hace que el resto tenga sentido en vez de ser recetas sueltas.
AI Fluency: Framework & Foundations (4h)
El marco 4D (Delegation, Description, Discernment, Diligence) que usa el propio Anthropic. Te da el criterio para decidir qué delegar a un agente y cómo juzgar si el resultado es correcto — clave para Agents & Workflows.
Building with the Claude API (9h) — aquí entras de lleno en CCDV-F
El curso grande: prompting, tool use, RAG, agentes, patrones de producción. A partir de aquí sigues con la guía específica del examen (dominios, pesos y plan semanal) que ya tienes preparada.
POR QUÉ TODO SUENA A CHINO SI YA USAS CLAUDE CODE A DIARIO
Claude Code es un agente que ya trae resuelta toda la capa que pregunta el examen. Tú escribes en lenguaje natural en el terminal; por debajo, Claude Code construye el array de mensajes, gestiona el system prompt, decide qué herramienta usar y en qué orden, reintenta si algo falla. Nunca ves ese código — por diseño, esa es la gracia de la herramienta.
✅ Esto NO es un problema de programación
Ya sabes Python, TypeScript, VS Code y ya escribes scripts que consumen APIs — la mecánica de "instalar un SDK, guardar una clave, hacer una petición HTTP" no es nueva para ti. El hueco es mucho más estrecho de lo que parece: es el esquema concreto de la API de Claude (cómo se forma el array messages, qué es un bloque tool_use, cómo se estructura la respuesta) — vocabulario específico, no una habilidad nueva que construir desde cero.

CÓMO FUNCIONA UN LLM POR DEBAJO — LO MÍNIMO INDISPENSABLE
Sin esto, el prompting y los agentes son recetas sueltas sin por qué. Con esto, todo lo que veas después encaja en un modelo mental.
Token
La unidad mínima de texto que procesa el modelo — no es una palabra, es un fragmento (a veces media palabra). Todo se mide y se paga en tokens: entrada y salida.
Context window
El total de tokens que el modelo puede "ver" a la vez (mensaje + system + historial + respuesta). Se agota, y tú eres responsable de gestionarlo en la API cruda.
Roles (user / assistant / system)
Cada mensaje del array lleva una etiqueta de quién "habla". El modelo predice el siguiente turno como si continuara un guion con esos roles.
stop_reason
El campo que te dice por qué el modelo dejó de generar: end_turn, max_tokens, o tool_use (quiere que ejecutes una herramienta y le devuelvas el resultado).
Streaming
Recibir la respuesta token a token en vez de esperar al mensaje completo — es lo que hace que Claude Code parezca "escribir en vivo".
temperature / max_tokens
Parámetros que controlas tú en cada llamada: cuánta aleatoriedad permites en la respuesta y cuántos tokens como máximo puede generar.

TU PRIMERA LLAMADA A LA API — LO ESPECÍFICO DE CLAUDE, NO LA MECÁNICA DE SCRIPTING
Te salto lo que ya sabes: crear proyecto, entorno virtual, instalar dependencias — eso ya lo dominas. Vamos directo al ejemplo mínimo para que veas por primera vez la forma exacta de la petición y la respuesta de Claude, que es lo único realmente nuevo aquí.
Crea tu clave en platform.claude.com → Settings → API keys (solo se muestra completa una vez). Guía oficial: Get your Claude API key. Instala pip install anthropic o npm install @anthropic-ai/sdk según prefieras.
Ejecuta el ejemplo de abajo tal cual, sin modificar nada, y fíjate en tres cosas que Claude Code te oculta: el system como parámetro explícito, el array messages que reconstruyes tú en cada turno, y el objeto usage con los tokens reales.
Cambia el content del mensaje y observa cómo varía usage. Después, fuerza un max_tokens muy bajo y mira el stop_reason cambiar a "max_tokens" — así ves ese campo en acción, no solo en la doc.
import anthropic

client = anthropic.Anthropic()  # lee ANTHROPIC_API_KEY solo

message = client.messages.create(
    model="claude-sonnet-5",
    max_tokens=1000,
    system="Responde siempre en una sola frase.",
    messages=[
        {"role": "user", "content": "¿Qué es un token en un LLM?"}
    ],
)

print(message.content[0].text)
print(message.usage)       # input_tokens y output_tokens reales
print(message.stop_reason) # "end_turn", "max_tokens" o "tool_use"
✅ Qué acabas de ver que Claude Code te ocultaba
No la mecánica de hacer una llamada — eso ya lo sabías. Lo nuevo es el esquema exacto de Claude: system como parámetro (no un archivo), messages como array que tú mantienes, y stop_reason/usage como campos concretos de la respuesta.
