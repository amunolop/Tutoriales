Migración por Semántica, no por Sintaxis
La clave: Los tests de integración y los diagramas arquitectónicos son la fuente de verdad. El código Java limpio es solo consultoría cuando la IA tiene dudas.
🎯

Tests = Contrato

Los tests de integración Playwright son agnósticos al lenguaje. Si pasan en Java y pasan en Go, el comportamiento es matemáticamente idéntico.

📐

Diagramas = Arquitectura

Los diagramas Mermaid documentan las decisiones de diseño que no están en el código. El "por qué" de las cosas viaja contigo.

☕

Java = Referencia

El código Java limpio sirve de consultoría cuando la IA tiene dudas, pero NO se copia línea a línea al nuevo lenguaje.

Por qué funciona
La mayoría de migraciones fallan porque:
❌ Reescriben sin tests → "creemos que funciona igual"
❌ Copian código viejo 1:1 → arrastran deuda técnica al nuevo lenguaje
❌ No documentan decisiones → pierden el "por qué" de las cosas
Tu enfoque:
✅ Tests = Red de seguridad matemática
✅ Código limpio = Referencia, no plantilla
✅ Diagramas = Conocimiento arquitectónico portable
Las 3 Fases
Proceso incremental y verificable en cada paso.
1

Red de Seguridad

Blindar el comportamiento actual antes de tocar una línea de código

1.1

Estabilizar el Entorno Local

Levantar el servidor Legacy (Tomcat/WildFly) y la base de datos de forma local. Garantizar que la aplicación responde a peticiones HTTP.

Terminal
1.2

Generar Tests de Integración (Playwright)

Escribir peticiones HTTP directas contra los Servlets antiguos. Validar códigos de estado, formato de salida (JSON/HTML) y alteraciones en la base de datos. Tratarlo como Caja Negra.

Cursor
1.3

Establecer la Línea Base (Baseline)

Ejecutar los tests de Playwright de forma iterativa hasta que pasen en verde al 100%. Esto certifica el comportamiento actual del negocio.

npx playwright test
2

Refactorización Java

Limpiar el código Java con la red de seguridad activa

2.1

Extraer Capa de Acceso a Datos (DAOs)

Sacar el código SQL y JDBC incrustado en los Servlets hacia clases DAO o Repositorios independientes.

Cursor Composer
2.2

Validar la Integración (Check 1)

Ejecutar la suite de Playwright sin modificar ninguna línea de los tests. Deben seguir en verde. Si alguno falla, la extracción del DAO ha alterado la lógica original.

Terminal
2.3

Aplicar Clean Code, SOLID y Jakarta EE

Transformar el Servlet en un controlador limpio. Extraer la lógica de negocio a clases de Servicio e inyectar las dependencias usando anotaciones modernas (@Inject).

Cursor Composer
2.4

Validación Definitiva del Refactor (Check 2)

Última ejecución de los tests de Playwright contra el código Java limpio. Si el resultado es positivo, el refactor arquitectónico está garantizado.

Terminal
2.5

Generar Diagramas Mermaid

Documentar la arquitectura MDSS, flujos de request y decisiones de diseño en diagramas Mermaid. Estos diagramas son portables al nuevo lenguaje.

Cursor
3

Salto Políglota

Reescritura en el nuevo lenguaje verificada matemáticamente

3.1

Migrar a Nueva Arquitectura/Lenguaje

Tomar el código Java limpio como mapa exacto para reescribir la API en el nuevo lenguaje. Generar Tests Unitarios automatizados para cada función aislada.

Claude Code CLI
3.2

Validar el Nuevo Backend (Check 3)

Apuntar los tests de integración originales de Playwright (creados en Fase 1) al puerto del nuevo servidor. El comportamiento externo debe ser matemáticamente idéntico.

Terminal
3.3

Despliegue Progresivo (Strangler Fig)

Configurar un proxy inverso (Nginx) para enrutar el tráfico mayoritario hacia el sistema Legacy, desviando progresivamente rutas específicas hacia el nuevo backend validado.

Ejemplo de Test de Integración
tests/integration/backend/perfil.spec.ts
TypeScript
import { test, expect } from '@playwright/test';

test('GET /perfil retorna sesión anónima inicial', async ({ request }) => {
  const response = await request.get('http://localhost/perfil');
  
  expect(response.status()).toBe(200);
  
  const body = await response.json();
  expect(body.username).toBe('anonimo');
  expect(body.rol).toBe('GUEST');
  expect(body.ultimoAcceso).toMatch(/^\d{4}-\d{2}-\d{2}T/);
});

test('POST /perfil actualiza rol y persiste', async ({ request }) => {
  // Primera petición: crear sesión
  const res1 = await request.get('http://localhost/perfil');
  const cookies = res1.headers()['set-cookie'];
  
  // Segunda petición: actualizar rol
  const res2 = await request.post('http://localhost/perfil', {
    headers: { 'Cookie': cookies },
    data: { rol: 'ADMIN' }
  });
  
  expect(res2.status()).toBe(200);
  
  // Tercera petición: verificar persistencia (simula failover)
  const res3 = await request.get('http://localhost/perfil', {
    headers: { 'Cookie': cookies }
  });
  
  const body = await res3.json();
  expect(body.rol).toBe('ADMIN');
});

Cronograma Realista
Estimación de tiempos para un proyecto con ~15 endpoints.

Semana 1: Tests de Integración Backend

Escribir tests Playwright para todos los endpoints. Ejecutar hasta verde al 100%. Baseline establecida.

Día 8-9: Documentación Arquitectónica

Generar diagramas Mermaid de arquitectura MDSS, flujos de request y decisiones de diseño.

Día 10: Migración con Claude Code CLI

Ejecutar migración políglota. Claude Code lee tests + diagramas y genera el proyecto completo en el nuevo lenguaje.

Día 11-12: Validación y Ajustes

Apuntar tests Playwright al nuevo backend. Si alguno falla, ajustar con Cursor. Iterar hasta verde.

Día 13-14: Tests E2E + Strangler Fig

Escribir tests E2E frontend+backend. Configurar Nginx para despliegue progresivo (patrón Strangler Fig).

Resultado: De 3 meses tradicionales a 14 días con IA, con mayor calidad y cero riesgo.
Checklist Pre-Migración
Asegúrate de cumplir todos estos puntos antes de ejecutar la migración políglota.
Tests de integración backend cubren todos los endpoints (GET, POST, PUT, DELETE)
Tests validan headers, cookies, códigos de estado, no solo el body JSON
Diagramas Mermaid documentan decisiones arquitectónicas (ej. por qué escritura post-respuesta)
Código Java está limpio y sin deuda técnica (DAOs extraídos, SOLID aplicado)
Tienes logs de producción para detectar edge cases no cubiertos en tests
CI valida que diagramas están sincronizados con docker-compose.yml
Tests cubren validaciones de negocio (ej. password incorrecta → 401)
Tests cubren edge cases (sesión expirada, sin sessionID, datos inválidos)
Playwright config tiene 3 projects (backend-integration, frontend-integration, e2e)
Entorno local levanta con docker-compose up y todos los servicios responden
Comandos Esenciales
Comandos que ejecutarás durante el proceso.
Instalación de Playwright
Bash
# Inicializar Playwright en el proyecto
npm init playwright@latest

# Instalar dependencias
npm install
Ejecutar Tests
Bash
# Ejecutar solo tests de backend
npx playwright test --project=backend-integration

# Ejecutar tests E2E
npx playwright test --project=e2e

# Ejecutar todos los tests
npx playwright test

# Ejecutar en modo UI (debug visual)
npx playwright test --ui

# Ver reporte de resultados
npx playwright show-report
Migración con Claude Code CLI
Bash
# Ejemplo de prompt para Claude Code CLI
claude-code migrate \
  --from java \
  --to go \
  --contracts "tests/integration/backend/**/*.spec.ts" \
  --architecture "tests/diagrams/*.mmd" \
  --reference "backend/src/main/java/" \
  --output "go-backend/"
Levantar Entorno
Bash
# Levantar backend Java actual
cd backend
docker-compose up --build

# Levantar nuevo backend (ej. Go)
cd go-backend
go run main.go

# Apuntar tests al nuevo backend
export API_URL=http://localhost:8080
npx playwright test --project=backend-integration
