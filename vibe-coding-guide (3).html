ÁRBOL DE DECISIÓN — ¿QUÉ HERRAMIENTA USAR?
💜 Usa Lovable si...
Quieres una app web con auth, BD y UI pulida en el menor tiempo posible. Necesitas GitHub sync para luego modificar con Cursor. El proyecto tiene formularios, dashboards y CRUD. Supabase como backend no te asusta.
🤖 Usa Emergent si...
Necesitas web + mobile (Android/iOS) desde el mismo prompt. Quieres Python en el backend. El proyecto tiene lógica de negocio compleja. Necesitas el menor lock-in posible — el código es tuyo desde el principio.
⚡ Usa Bolt si...
Quieres iterar rápido en el frontend con código limpio. El proyecto es frontend-heavy. Prefieres arrancar sin BD y añadirla después. Quieres el código más limpio y portable de todos.
🔄 Usa Replit si...
Necesitas cualquier lenguaje (Python, Rust, Go). Quieres un entorno todo-en-uno sin instalar nada. El proyecto es un script, bot, API o backend puro. No te importa el lock-in a cambio de velocidad.

LIMITACIONES A CONOCER
⚠️ El lock-in de Supabase
Todo el backend de Lovable es Supabase. Auth, BD, storage, real-time. Si quieres migrar a otro backend (tu propio servidor, Firebase, PlanetScale) hay que reescribir toda la capa de datos. Evalúa si Supabase es suficiente para tu proyecto a largo plazo antes de empezar.
💡 El flujo híbrido ideal con Lovable
Genera el 80% en Lovable (estructura, auth, CRUD, UI). Conecta GitHub. Clona el repo. Abre en Cursor con Copilot. El 20% restante (lógica compleja, optimizaciones, integraciones específicas) lo haces en local con control total. Push a GitHub → Vercel despliega automáticamente.

CUÁNDO BOLT ES LA MEJOR OPCIÓN
✅ Prototipos rápidos
Quieres mostrar algo en funcionamiento en menos de una hora. Reunión en 2 horas y necesitas un demo. Sin BD, sin auth — solo la UI funcionando.
✅ Frontend-heavy
Apps donde el 80% del trabajo es la UI — dashboards, portfolios, landing pages, visualizaciones de datos. Bolt genera el mejor código frontend de todos.
✅ Punto de partida
Genera la estructura y los componentes en Bolt, exporta, y añade el backend en local. Es más rápido que empezar desde cero con Vite manualmente.
❌ Backend complejo
Si necesitas lógica server-side compleja, colas de mensajes, workers en background o múltiples microservicios — Bolt no es la herramienta. Usa Emergent o Replit.

EL LOCK-IN DE REPLIT — ENTENDERLO ANTES DE COMPROMETERSE
⚠️ Neon PostgreSQL y el hosting propio crean dependencia
La BD de Replit es Neon PostgreSQL (serverless). Si en algún momento quieres mover la app fuera de Replit, necesitas: (1) exportar el esquema y los datos de Neon, (2) montar una BD en otro sitio, (3) cambiar la connection string. No es imposible pero requiere trabajo. Si sabes desde el principio que la app irá a producción fuera de Replit, exporta el código pronto y trabaja en local desde ese momento.
💡 El caso de uso ideal de Replit
Backends y APIs en Python. Scripts que necesitan correr en la nube sin servidor propio. Prototipos donde el lenguaje no es JavaScript. Proyectos colaborativos donde varios desarrolladores trabajan en tiempo real. Bots (Discord, Telegram, Slack) que necesitan un hosting siempre encendido. Para estos casos, Replit es insuperable en velocidad de setup.

RUTA A: PWA — LA MÁS RÁPIDA
Una PWA es una web que el usuario puede "instalar" en su móvil. No pasa por la Play Store. El usuario va a tu URL desde Chrome/Safari y le sale el banner "Añadir a pantalla de inicio". Se comporta casi como una app nativa — tiene icono, va fullscreen, puede funcionar offline y puede recibir notificaciones push. 
// Añadir PWA a cualquier app React (Lovable, Bolt, Emergent web)
npm install vite-plugin-pwa

// vite.config.ts
import { VitePWA } from 'vite-plugin-pwa';

export default {
  plugins: [
    VitePWA({
      registerType: 'autoUpdate',
      manifest: {
        name: 'Mi App de Proyectos',
        short_name: 'Proyectos',
        description: 'Gestión de proyectos',
        theme_color: '#1a1410',
        background_color: '#f5f0e8',
        display: 'standalone',  // fullscreen, sin barra del navegador
        icons: [
          { src: '/icon-192.png', sizes: '192x192', type: 'image/png' },
          { src: '/icon-512.png', sizes: '512x512', type: 'image/png' },
        ]
      }
    })
  ]
}
RUTA B: CAPACITOR — WEB → APK REAL
Capacitor envuelve tu app web en una shell nativa. El resultado es un APK (Android) o IPA (iOS) real que se publica en las tiendas. Tiene acceso completo a las APIs nativas: cámara, GPS, notificaciones push, biometría, almacenamiento local. Es el puente entre Lovable/Bolt y las tiendas oficiales. 
# Añadir Capacitor a tu app de Lovable/Bolt
npm install @capacitor/core @capacitor/cli
npx cap init "Mi App" "com.miempresa.miapp"
npm install @capacitor/android @capacitor/ios

# Construir la web primero
npm run build                  # genera carpeta dist/

# Sincronizar con los proyectos nativos
npx cap add android
npx cap add ios
npx cap sync                   # copia dist/ a los proyectos nativos

# Abrir en Android Studio para generar el APK
npx cap open android

# En Android Studio: Build → Generate Signed APK/AAB
# El AAB es el formato que acepta la Play Store
# Acceso a APIs nativas con Capacitor
import { Camera } from '@capacitor/camera';
import { Geolocation } from '@capacitor/geolocation';

from langgraph.graph import StateGraph, END
from langchain_anthropic import ChatAnthropic
from typing import TypedDict, List

# ── ESTADO COMPARTIDO ENTRE TODOS LOS AGENTES ──────────
class EstadoProyecto(TypedDict):
    prompt_usuario: str
    arquitectura: str          # output del Architect
    schema_bd: str             # output del DB Designer
    codigo_backend: str        # output del Backend Dev
    codigo_frontend: str       # output del Frontend Dev

# ── DEFINIR LOS NODOS (cada uno es una función/agente) ─

opus  = ChatAnthropic(model="claude-opus-4-6")
