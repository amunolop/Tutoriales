Change Detection — OnPush

Con la estrategia OnPush, Angular deja de revisar el componente en cada ciclo. Solo se marca como "dirty" en tres casos concretos.

¿Cuándo se revisa un componente OnPush?

✓
Cambia la referencia de un @Input() — no basta mutar el objeto, hay que crear uno nuevo.
✓
Un evento del DOM ocurre dentro del propio componente (click, keyup, etc.).
✓
Un Observable emite un valor a través del pipe | async en el template.
⚡ mi-componente.component.ts rendimiento 
import { Component, ChangeDetectionStrategy } from '@angular/core';

@Component({
  selector: 'app-mi-componente',
  templateUrl: './mi-componente.component.html',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class MiComponente {
  // Solo se actualizará si cambia la referencia del @Input
  // o si un evento del DOM ocurre dentro de este componente
}
⚠️ Error común: en un componente OnPush, si haces this.items.push(newItem), la vista NO se actualiza porque la referencia del array no cambió. Necesitas this.items = [...this.items, newItem].

Inmutabilidad

La clave de OnPush: siempre crear nuevas referencias en lugar de mutar objetos existentes.

📋 patrones-inmutabilidad.ts rendimiento 
// ═══════ ARRAYS ═══════

// ❌ Muta — OnPush NO detecta el cambio
this.items.push(newItem);
this.items.splice(index, 1);

// ✅ Inmutable — crea nueva referencia
this.items = [...this.items, newItem];                   // agregar
this.items = this.items.filter((_, i) => i !== index);    // eliminar
this.items = this.items.map(i => i.id === id ? updated : i); // actualizar


// ═══════ OBJETOS ═══════

// ❌ Muta
this.user.name = 'Nuevo';

// ✅ Inmutable
this.user = { ...this.user, name: 'Nuevo' };


// ═══════ OBJETOS ANIDADOS ═══════

// ✅ Spread profundo
this.config = {
  ...this.config,
  ui: { ...this.config.ui, theme: 'dark' }
};
Tip: con formularios reactivos, patchValue() ya crea internamente nuevas referencias — no necesitas preocuparte por la inmutabilidad dentro del FormGroup.

patchValue y getRawValue

El patrón Data Mapping — cómo mover datos entre el backend JSON y el formulario reactivo.

📝 editar-usuario.component.ts formulario 
export class EditarUsuarioComponent implements OnInit {
  form = this.fb.group({
    nombre:   ['', Validators.required],
    email:    ['', [Validators.required, Validators.email]],
    // disabled → no aparece en .value pero SÍ en getRawValue()
    codigoInterno: [{ value: '', disabled: true }]
  });

  ngOnInit() {
    this.api.getUsuario(id).subscribe(data => {
      this.form.patchValue(data);  // ← carga parcial del JSON
    });
  }

  guardar() {
    const payload = this.form.getRawValue();  // ← incluye disabled
    this.api.update(payload).subscribe();
  }
}
📋 Comparativa 
Método            Incluye disabled   Carga parcial   Uso típico
────────────────  ─────────────────  ──────────────  ──────────────────────
setValue()         No                 No (requiere    Carga completa
                                     todos los       del formulario
                                     campos)
patchValue()      No                 Sí              Carga desde API
.value            No                 —               Lectura rápida
getRawValue()     Sí ✅              —               Enviar al backend

ControlValueAccessor (CVA)

El patrón que permite que un componente hijo funcione como un control de formulario nativo. Así puedes usar formControlName directamente sobre tu componente custom.

🔗 selector-pais.component.ts CVA 
import { ControlValueAccessor, NG_VALUE_ACCESSOR } from '@angular/forms';

@Component({
  selector: 'app-selector-pais',
  template: `<select (change)="onChange($event.target.value)">...</select>`,
  providers: [{
    provide: NG_VALUE_ACCESSOR,
    useExisting: SelectorPaisComponent,
    multi: true
  }]
})
export class SelectorPaisComponent implements ControlValueAccessor {
  valor: string = '';

  // Angular llama este método para pasarte el valor del form
  writeValue(val: string): void { this.valor = val; }

  // Registra la función que notifica al form padre de cambios
  registerOnChange(fn: any): void { this.onChange = fn; }

  // Registra la función para cuando el control pierde el foco
  registerOnTouched(fn: any): void { this.onTouched = fn; }

  onChange = (val: string) => {};
  onTouched = () => {};
}
Uso en el padre: <app-selector-pais formControlName="pais"></app-selector-pais> — funciona exactamente igual que un <input> nativo.

FormArray — Listas dinámicas

Gestión de colecciones dinámicas de controles. Ideal para múltiples documentos, direcciones o líneas de pedido.

📄 documentos-form.component.ts dinámico 
export class DocumentosFormComponent {
  form = this.fb.group({
    documentos: this.fb.array([])
  });

  get documentos(): FormArray {
    return this.form.get('documentos') as FormArray;
  }

  agregarDoc() {
    this.documentos.push(this.fb.group({
      tipo:   ['', Validators.required],
      numero: ['', Validators.required]
    }));
  }

  eliminarDoc(i: number) {
    this.documentos.removeAt(i);
  }

Tip: siempre crea un getter tipado para acceder al FormArray. Evita castear en cada uso y mantiene el template limpio: *ngFor="let doc of documentos.controls; let i = index".

BehaviorSubject — Estado local

Gestión reactiva del estado de la UI: spinners, mensajes de error, datos del usuario. A diferencia de Subject, siempre tiene un valor inicial y emite el último valor a los nuevos suscriptores.

🔄 usuario.service.ts RxJS 
import { BehaviorSubject, Observable } from 'rxjs';

@Injectable({ providedIn: 'root' })
export class UsuarioService {
  private loading$ = new BehaviorSubject<boolean>(false);
  private error$   = new BehaviorSubject<string | null>(null);

  // Exponer como Observable (solo lectura)
  isLoading$: Observable<boolean> = this.loading$.asObservable();
  error:      Observable<string | null> = this.error$.asObservable();

  cargarUsuario(id: number) {
    this.loading$.next(true);
    this.error$.next(null);

    return this.http.get<Usuario>(`/api/users/${id}`).pipe(
      finalize(() => this.loading$.next(false)),
      catchError(err => {
        this.error$.next(err.message);
        return EMPTY;
      })
    );
  }
}
// Template: *ngIf="service.isLoading$ | async"

switchMap vs mergeMap vs concatMap

Los tres operadores de "aplanamiento" de RxJS. Saber cuándo usar cada uno es clave a nivel senior.

📋 Comparativa de operadores 
Operador      Cancela anterior    Concurrencia    Caso de uso
────────────  ──────────────────  ──────────────  ─────────────────────────
switchMap     Sí ✅               1               Búsquedas typeahead
mergeMap      No                  ∞ (configurable) Descargas en paralelo
concatMap     No                  1 (en serie)     Orden garantizado
exhaustMap   Ignora nuevas       1               Doble-click en submit
🔍 buscador.component.ts switchMap 
// switchMap — cancela la petición anterior si el usuario sigue tecleando
this.searchControl.valueChanges.pipe(
  debounceTime(300),
  distinctUntilChanged(),
  switchMap(term => this.api.buscar(term))
).subscribe(results => this.resultados = results);
📥 descargas.service.ts mergeMap 
// mergeMap — descarga hasta 3 archivos en paralelo
from(archivos).pipe(
  mergeMap(archivo => this.http.get(archivo.url, {
    responseType: 'blob'
  }), 3)  // ← concurrencia máxima: 3
).subscribe(blob => this.guardarArchivo(blob));

Panel de Descargas — Blobs

Patrón avanzado para descargar archivos, mostrar progreso y limpiar memoria.

💾 download.util.ts blob 
descargarArchivo(blob: Blob, nombre: string): void {
  const url = URL.createObjectURL(blob);
  const a   = document.createElement('a');
  a.href     = url;
  a.download = nombre;
  a.click();

  // ⚠️ Liberar la memoria — sin esto hay memory leak
  URL.revokeObjectURL(url);
}
⚠️ Memory Leak: cada createObjectURL reserva memoria en el navegador hasta que se cierre la pestaña o se llame revokeObjectURL. En un panel de descargas con muchos archivos, esto puede acumularse rápidamente.

Herencia de Componentes

Compartir lógica de ciclo de vida y métodos comunes usando una clase base abstracta.

🏗️ base-viewer.component.ts patrón 
export abstract class BaseViewerComponent implements OnInit, OnDestroy {
  protected destroy$ = new Subject<void>();

  abstract cargarDatos(): void;

  ngOnInit() {
    this.cargarDatos();
  }

  ngOnDestroy() {
    this.destroy$.next();
    this.destroy$.complete();
  }
}

// Componente hijo — hereda OnDestroy automáticamente
@Component({ /* ... */ })
export class PdfViewerComponent extends BaseViewerComponent {
  cargarDatos() {
    this.api.getPdf(id).pipe(
      takeUntil(this.destroy$)
    ).subscribe();
  }
}

Interceptors HTTP

Captura global de errores y gestión automática de tokens de autenticación.

🔐 auth.interceptor.ts seguridad 
@Injectable()
export class AuthInterceptor implements HttpInterceptor {

  constructor(private auth: AuthService) {}

  intercept(req: HttpRequest<any>, next: HttpHandler): Observable<HttpEvent<any>> {
    const token = this.auth.getToken();
    const authReq = req.clone({
      setHeaders: { Authorization: `Bearer ${token}` }
    });

    return next.handle(authReq).pipe(
      catchError((error: HttpErrorResponse) => {
        if (error.status === 401) {
          this.auth.logout();
        }
        return throwError(() => error);
      })
    );
  }
}
Registro: en NgModules se registra en providers con HTTP_INTERCEPTORS. En standalone, se usa provideHttpClient(withInterceptors([authInterceptor])).

Manejo de Memory Leaks

Dos fuentes principales de fugas de memoria en Angular: suscripciones no cerradas y URLs de objetos no liberadas.

🧹 Patrones de limpieza memoria 
// ═══════ PATRÓN 1: takeUntil + Subject ═══════
private destroy$ = new Subject<void>();

ngOnInit() {
  this.service.datos$.pipe(
    takeUntil(this.destroy$)
  ).subscribe();
}

ngOnDestroy() {
  this.destroy$.next();
  this.destroy$.complete();
}


// ═══════ PATRÓN 2: Pipe async (automático) ═══════
// En el template: {{ datos$ | async }}
// Angular se desuscribe solo al destruir el componente ✅


// ═══════ PATRÓN 3: revokeObjectURL ═══════
const url = URL.createObjectURL(blob);
// ... usar url ...
URL.revokeObjectURL(url); // ← OBLIGATORIO
Preferir | async: es la forma más segura porque Angular maneja automáticamente la suscripción y desuscripción. Además, funciona perfectamente con OnPush.

Interfaces vs Types — Cuándo usar cada uno

TypeScript ofrece interface y type para definir formas de datos. En Angular, el estándar es usar interfaces para modelos de datos y types para uniones/utilidades.

📐 models/usuario.model.ts interfaces 
// ═══════ INTERFACES — para modelos de datos ═══════

export interface Usuario {
  id:        number;
  nombre:    string;
  email:     string;
  rol:       Rol;
  activo:    boolean;
  direccion: Direccion;
}

export interface Direccion {
  calle:    string;
  ciudad:   string;
  codigoPostal: string;
}

// Interfaces para respuestas de API
export interface ApiResponse<T> {
  data:    T;
  status:  number;
  message: string;
}

export interface PaginatedResponse<T> extends ApiResponse<T[]> {
  total:       number;
  page:        number;
  pageSize:    number;
}
🔧 models/tipos-utilidad.ts types 
// ═══════ TYPES — para uniones, alias y utilidades ═══════

export type Rol = 'admin' | 'editor' | 'viewer';

export type EstadoPedido = 'pendiente' | 'procesando' | 'enviado' | 'entregado';

// Tipo derivado — crea una versión parcial para formularios
export type UsuarioForm = Omit<Usuario, 'id'>;

// Tipo para payloads de actualización parcial
export type UsuarioUpdate = Partial<Pick<Usuario, 'nombre' | 'email' | 'rol'>>;

// Callback tipado
export type OnChangeCallback<T> = (value: T) => void;
📋 Cuándo usar cada uno 
Escenario                         interface    type
────────────────────────────────  ───────────  ──────────
Modelos de datos (User, Product)  ✅ Sí         Posible
Respuestas de API                 ✅ Sí         Posible
Contratos de servicios            ✅ Sí         No
Uniones de strings (roles)        No           ✅ Sí
Utility types (Pick, Omit)        No           ✅ Sí
Tipos derivados o mapeados       No           ✅ Sí
Extensión / herencia de formas    ✅ extends    & intersección
Regla práctica: si describe la forma de un objeto que viaja entre capas (API → servicio → componente), usa interface. Si necesitas uniones, alias o tipos derivados, usa type.

Genéricos en Servicios

Un servicio base tipado evita repetir la misma lógica CRUD en cada servicio. Los genéricos garantizan que cada instancia trabaje con su tipo correcto.

🔗 base-crud.service.ts genérico 
export abstract class BaseCrudService<T> {
  constructor(
    protected http: HttpClient,
    protected endpoint: string
  ) {}

  getAll(): Observable<T[]> {
    return this.http.get<T[]>(this.endpoint);
  }

  getById(id: number): Observable<T> {
    return this.http.get<T>(`${this.endpoint}/${id}`);
  }

  create(body: Partial<T>): Observable<T> {
    return this.http.post<T>(this.endpoint, body);
  }

  update(id: number, body: Partial<T>): Observable<T> {
    return this.http.put<T>(`${this.endpoint}/${id}`, body);
  }

  delete(id: number): Observable<void> {
    return this.http.delete<void>(`${this.endpoint}/${id}`);
  }
}

// ═══════ USO ═══════
@Injectable({ providedIn: 'root' })
export class UsuarioService extends BaseCrudService<Usuario> {
  constructor(http: HttpClient) {
    super(http, '/api/usuarios');
  }
}
// UsuarioService.getAll() devuelve Observable<Usuario[]> ✅

Strict Mode — tsconfig

Angular con strict: true activa todas las comprobaciones estrictas de TypeScript. Es imprescindible en proyectos senior.

⚙️ tsconfig.json config 
{
  "compilerOptions": {
    "strict": true,                   // activa TODOS los flags de abajo
    "strictNullChecks": true,        // null y undefined son tipos distintos
    "strictPropertyInitialization": true, // propiedades deben inicializarse
    "noImplicitAny": true,           // prohíbe any implícito
    "noImplicitReturns": true,       // todas las ramas deben retornar
    "strictTemplates": true          // ← Angular: verifica tipos en templates
  }
}
📋 Errores comunes con strictNullChecks 
// ❌ Error: Object is possibly 'undefined'
const nombre = usuario.direccion.calle;

// ✅ Optional chaining
const nombre = usuario.direccion?.calle;

// ✅ Non-null assertion (solo cuando estás 100% seguro)
const nombre = usuario.direccion!.calle;

// ✅ Narrowing con guard
if (usuario.direccion) {
  const nombre = usuario.direccion.calle; // ← TypeScript sabe que existe
}
any vs unknown: evita any a toda costa. Si no conoces el tipo, usa unknown — te obliga a hacer type narrowing antes de usarlo, lo cual es más seguro.

Spies y Mocks de Servicios

Aislar el componente de sus dependencias usando jasmine.createSpyObj.

// ═══════ CREAR EL MOCK ═══════
const mockServicio = jasmine.createSpyObj('UsuarioService', [
  'getData', 'save', 'delete'

// Configurar respuestas
mockServicio.getData.and.returnValue(of({ nombre: 'Test', id: 1 }));
mockServicio.save.and.returnValue(of({ success: true }));

  { provide: UsuarioService, useValue: mockServicio }

  expect(mockServicio.getData).toHaveBeenCalled();

HttpClientTestingModule

Testear servicios que hacen peticiones HTTP sin tocar el backend real. HttpTestingController intercepta y simula respuestas.

🌐 usuario.service.spec.ts HTTP 
import { HttpClientTestingModule, HttpTestingController }
  from '@angular/common/http/testing';

let service: UsuarioService;
let httpMock: HttpTestingController;

beforeEach(() => {
  TestBed.configureTestingModule({
    imports: [HttpClientTestingModule],
    providers: [UsuarioService]
  });
  service  = TestBed.inject(UsuarioService);
  httpMock = TestBed.inject(HttpTestingController);
});

it('debería obtener usuarios (GET)', () => {
  const mockUsers: Usuario[] = [
    { id: 1, nombre: 'Ana', email: 'ana@mail.com' }
  ];

  service.getAll().subscribe(users => {
    expect(users.length).toBe(1);
    expect(users[0].nombre).toBe('Ana');
  });

  const req = httpMock.expectOne('/api/usuarios');
  expect(req.request.method).toBe('GET');
  req.flush(mockUsers);  // ← simula la respuesta
});

it('debería manejar error 500', () => {
  service.getAll().subscribe({
    error: (err) => expect(err.status).toBe(500)
  });

  const req = httpMock.expectOne('/api/usuarios');
  req.flush('Server Error', {
    status: 500, statusText: 'Internal Server Error'
  });
});

afterEach(() => {
  httpMock.verify();  // ← verifica que no hay peticiones pendientes
});
⚠️ Nunca olvides httpMock.verify() en el afterEach. Detecta peticiones HTTP no esperadas o no consumidas, que normalmente indican un bug en el test o en el servicio.

fakeAsync y tick

Controlar el tiempo en tests asíncronos. fakeAsync crea una zona simulada y tick avanza el reloj virtual.

⏱️ buscador.component.spec.ts async 
import { fakeAsync, tick } from '@angular/core/testing';

it('debería hacer debounce de 300ms en la búsqueda',
  fakeAsync(() => {
    component.searchControl.setValue('angular');

    // A los 100ms NO se ha llamado aún
    tick(100);
    expect(mockServicio.buscar).not.toHaveBeenCalled();

    // A los 300ms SÍ se dispara
    tick(200);  // total: 300ms
    expect(mockServicio.buscar).toHaveBeenCalledWith('angular');
  })
);

it('debería resolver un setTimeout',
  fakeAsync(() => {
    let done = false;
    setTimeout(() => done = true, 1000);

    tick(1000);
    expect(done).toBeTrue();
  })
);

it('debería avanzar todo el tiempo pendiente',
  fakeAsync(() => {
    component.iniciarPolling();  // setInterval cada 5s

    tick(15000);  // simula 15 segundos
    expect(mockServicio.refresh).toHaveBeenCalledTimes(3);

    discardPeriodicTasks();  // limpia timers pendientes
  })
);
waitForAsync vs fakeAsync: waitForAsync espera a que las promesas reales se resuelvan (más lento). fakeAsync + tick simula el paso del tiempo instantáneamente — siempre preferible para debounce, polling y timeouts.

Karma ejecuta los tests de Jasmine en un navegador real. Configurar umbrales de cobertura asegura la calidad del código.

⚙️ karma.conf.js config 
module.exports = function(config) {
