Prompts, Skills, Agentes y MCP
Los 4 conceptos que lo explican todo

Cada uno se apoya en el anterior: un prompt es la unidad mínima, una skill empaqueta prompts reutilizables, un agente ejecuta un bucle autónomo usando skills y herramientas, y MCP conecta ese agente con el mundo exterior. Con esto tienes el 90% — al final te digo el 10% que falta.

Ninguno sustituye al anterior — cada uno lo usa por debajo. Un agente no es "magia nueva": es un modelo que recibe prompts (a veces empaquetados en skills) y decide, en un bucle, cuándo usar una herramienta — y MCP es simplemente el estándar con el que esa herramienta puede vivir fuera de tu proyecto (una base de datos, GitHub, Notion...).
Prompt
Lo que le escribes al modelo. Puede ser una pregunta suelta o una instrucción persistente (custom instructions) que aplica siempre.
Skill
Un prompt — o conjunto de instrucciones — guardado como archivo SKILL.md reutilizable, para no reescribir lo mismo cada vez.
Agente
El modelo en modo "actúa, no solo respondas": inspecciona tu workspace, edita archivos, ejecuta comandos, corre tests, y repite hasta terminar la tarea.
MCP
El protocolo que deja a ese agente conectarse a sistemas externos (bases de datos, GitHub, documentación) sin que cada integración sea código a medida.
✅ Dato clave para VS Code
Estos 4 conceptos no son exclusivos de Claude: en 2026, GitHub Copilot los implementa con el mismo vocabulario y, en el caso de Skills y MCP, con el mismo formato de archivo. Aprenderlos una vez te sirve para los dos ecosistemas.
QUÉ ES UN PROMPT
La instrucción en lenguaje natural que le das al modelo. Puede ser de un solo uso (una pregunta en el chat) o persistente (una instrucción que se aplica siempre, en cada interacción).

✅ El truco que ya conoces de los conectores/preposiciones
Un buen prompt técnico sigue la misma lógica que ya practicaste en la plantilla de inglés: decisión + contexto + resultado esperado. "Genera tests" es un prompt pobre. "Genera tests unitarios con pytest para esta función, cubriendo los casos límite de valores negativos y nulos" es un prompt que un agente puede ejecutar sin adivinar.
QUÉ ES UNA SKILL
Un conjunto de instrucciones reutilizables que le enseñan a un agente cómo hacer una tarea concreta — no es una pregunta puntual, es un manual de procedimiento que el agente consulta cuando lo necesita.
EL FORMATO: SKILL.MD
Una skill es normalmente una carpeta con un archivo SKILL.md (metadatos + instrucciones en Markdown) y, opcionalmente, scripts o plantillas de apoyo. El agente no carga todo de golpe: solo lee el detalle completo de la skill cuando la tarea la necesita — así no gasta contexto en instrucciones irrelevantes. 
# Estructura típica de una skill
mi-skill/
├── SKILL.md          # nombre, descripción, cuándo usarla
├── ejemplos/
└── scripts/
✅ Interoperabilidad real (no solo teoría)
Desde 2026, el mismo archivo SKILL.md que usa Claude Code funciona también en Copilot agent mode, a través de .github/copilot-instructions.md y archivos SKILL.md a nivel de proyecto. No es una coincidencia de nombres — es el mismo estándar abierto, adoptado por los dos ecosistemas.
EJEMPLOS DE SKILLS ÚTILES EN DESARROLLO
code-review-checklist
Enseña al agente tu checklist concreto de revisión de PRs: convenciones de tu equipo, qué patrones evitar, qué comentar siempre.
generate-tests
Cómo estructurar tests para tu stack concreto (framework, mocks, cobertura mínima esperada).
db-migration-runner
Procedimiento paso a paso para generar y validar una migración de base de datos siguiendo tus convenciones.
QUÉ ES UN AGENTE
Un modelo que no solo responde texto: ejecuta un bucle — percibe el estado (tu código, un error), decide qué herramienta usar, actúa, observa el resultado, y repite hasta terminar la tarea o pedir tu confirmación.

⚠️ Un agente no es infalible por ser autónomo
Cuanta más autonomía le das, más importante es que sepas leer lo que hizo — un agente puede completar una tarea "con éxito" y haberlo hecho mal. La autonomía multiplica la velocidad, no sustituye tu criterio.
QUÉ ES MCP (MODEL CONTEXT PROTOCOL)
Un protocolo abierto que estandariza cómo un agente se conecta a herramientas y datos externos — bases de datos, GitHub, Notion, navegadores — sin que cada integración sea código a medida. Modelo cliente-servidor: el agente es el cliente MCP, y cada sistema externo expone un servidor MCP con un contrato común.

↔
Servidor MCPGitHub, DB, docs...
CÓMO SE VE ESTO EN VS CODE + COPILOT
Soporte de MCP disponible para todos los usuarios de VS Code desde julio de 2025, con gobernanza empresarial (listas de servidores permitidos) añadida en 2026 para entornos corporativos.
✅ La mayoría de servidores MCP son universales
Un servidor MCP construido para Claude Code normalmente también funciona en Copilot agent mode — es el mismo protocolo, y el servidor no distingue quién lo llama. Ejemplos habituales: el servidor MCP de GitHub (open source), servidores de bases de datos, servidores de documentación interna.
⚠️ Más capacidad = más superficie de riesgo
Cada servidor MCP que conectas le da al agente acceso a un sistema real. La recomendación general: empieza con un solo servidor, bien acotado, antes de conectar varios a la vez — MCP no es obligatorio para usar agent mode, es una capa adicional que añades cuando la necesitas.
CON ESTO TIENES EL 90% — EL 10% QUE FALTA ES OFICIO, NO CONCEPTOS NUEVOS
Ninguno de estos 6 puntos es "otro concepto que aprender desde cero" — son habilidades prácticas que se construyen usando los 4 pilares de arriba, no añadiendo un quinto pilar.
1 · Gestión del contexto
Cómo VS Code indexa tu proyecto (búsqueda semántica del código) para que el agente encuentre lo relevante sin que tú se lo señales todo a mano.
2 · Permisos y seguridad
Quién aprueba qué ejecuta el agente — listas de servidores MCP permitidos, confirmación de comandos antes de ejecutarlos, evitar dar acceso a sistemas sensibles sin control.
3 · Evaluar el resultado
No puedes confiar ciegamente en lo que produce el agente. Necesitas criterio propio para revisar y testear su output — esto es exactamente el "Discernment" del framework 4D que ya viste en AI Fluency.
4 · Depurar un agente que falla
Entender por qué se atasca en un bucle, por qué elige mal una herramienta, o por qué "termina con éxito" habiendo hecho algo distinto de lo que pediste.
5 · Conciencia de coste
Con modelos premium y planes de uso por créditos, entender qué tipo de tarea consume más — un agente que itera mucho no es gratis.
6 · Versionar tus instrucciones
Tratar tus custom instructions y skills como código: revisarlas, mejorarlas y versionarlas con el tiempo, no escribirlas una vez y olvidarlas.
✅ En resumen
Prompts + Skills + Agentes + MCP te dan el vocabulario y las piezas. El 10% restante es criterio de uso — y ese criterio solo se construye usándolo de verdad en tu día a día con VS Code, no leyendo un concepto más.
