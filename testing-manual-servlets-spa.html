ArquitecturaSPA + API REST + Servlets

Tu app tiene 3 capas claras que se testean de forma diferente. El navegador ejecuta la SPA (Vanilla JS), que habla con el backend (Servlets Java) vía REST JSON. Cada capa tiene sus herramientas y su nivel de la pirámide.

Frontend
SPA · Vanilla JS
HTML + CSS + JavaScript vanilla. Fetch API para llamar al backend. Web Components opcionales. Sin framework.
→
API REST
HTTP JSON

→
Backend
Java Servlets
HttpServlet sobre Tomcat. 3 capas: Servlet (controller) → Service (lógica) → DAO/Repository (datos).
La pirámide de tests para tu stack
Principio: Muchos tests rápidos abajo (unit), menos en el medio (integración), pocos arriba (E2E). Cada nivel cubre lo que el inferior no puede. No dupliques lo que ya cubre otro nivel.

Regla de oro: qué NO testear
✗ No testees:
• Getters y setters triviales
• Constructores sin lógica
• Código de frameworks/librerías
• El propio servidor Tomcat
• CSS / layout visual (eso es QA visual, no funcional)
• Logs (console.log, Logger)
✓ Sí testea:
• Toda lógica de negocio (cálculos, validaciones)
• Cada endpoint REST (happy path + error paths)
• Transformaciones de datos (DTO ↔ Entity, JSON parse)
• Edge cases: null, vacío, límites, concurrencia
• Seguridad: auth, permisos, input sanitization
• Que el front llama al endpoint correcto
Unit Test del Service — lógica de negocio
Patrón: Testea el Service con el DAO mockeado. Verifica que la lógica de negocio funciona sin depender de la BD. Usa @Mock para las dependencias y @InjectMocks para el SUT (System Under Test).
// ContratoServiceTest.java
// Test del Service con DAO mockeado — puro unit test

import static org.junit.jupiter.api.Assertions.*;
import static org.mockito.Mockito.*;

@ExtendWith(MockitoExtension.class)
class ContratoServiceTest {

    @Mock
    private ContratoDao contratoDao;

    @InjectMocks
    private ContratoService service;

    @Test
    void getById_existente_retornaContrato() {
        // GIVEN — preparar el escenario
        Contrato esperado = new Contrato(1L, "CLT-001", "Activo");
        when(contratoDao.findById(1L)).thenReturn(esperado);

        // WHEN — ejecutar la acción
        Contrato resultado = service.getById(1L);

        // THEN — verificar resultado
        assertNotNull(resultado);
        assertEquals("CLT-001", resultado.getCodigo());
        assertEquals("Activo", resultado.getEstado());
        verify(contratoDao, times(1)).findById(1L);
    }

    @Test
    void getById_noExiste_lanzaExcepcion() {
        // GIVEN
        when(contratoDao.findById(99L)).thenReturn(null);

        // WHEN + THEN
        ContratoNotFoundException ex = assertThrows(
            ContratoNotFoundException.class,
            () -> service.getById(99L)
        );
        assertEquals("Contrato no encontrado: 99", ex.getMessage());
    }

    @Test
    void crear_conDatosValidos_guardaYRetorna() {
        // GIVEN
        ContratoDto dto = new ContratoDto("CLT-002", "Pendiente");
        Contrato guardado = new Contrato(2L, "CLT-002", "Pendiente");
        when(contratoDao.save(any(Contrato.class))).thenReturn(guardado);

        // WHEN
        Contrato resultado = service.crear(dto);

        // THEN
        assertNotNull(resultado.getId());
        assertEquals("CLT-002", resultado.getCodigo());
        verify(contratoDao).save(any(Contrato.class));
    }
}
Unit Test del Servlet — mockear Request/Response
// ContratoServletTest.java
// Test del Servlet con HttpServletRequest/Response mockeados

@ExtendWith(MockitoExtension.class)
class ContratoServletTest {

    @Mock private ContratoService service;
    @Mock private HttpServletRequest request;
    @Mock private HttpServletResponse response;

    private ContratoServlet servlet;
    private StringWriter responseWriter;

    @BeforeEach
    void setUp() throws Exception {
        servlet = new ContratoServlet(service);
        responseWriter = new StringWriter();
        when(response.getWriter()).thenReturn(new PrintWriter(responseWriter));
    }

    @Test
    void doGet_conId_retornaJsonYStatus200() throws Exception {
        // GIVEN
        when(request.getPathInfo()).thenReturn("/1");
        Contrato c = new Contrato(1L, "CLT-001", "Activo");
        when(service.getById(1L)).thenReturn(c);

        // WHEN
        servlet.doGet(request, response);

        // THEN
        verify(response).setStatus(200);
        verify(response).setContentType("application/json");
        String json = responseWriter.toString();
        assertTrue(json.contains("CLT-001"));
    }

    @Test
    void doGet_noExiste_retorna404() throws Exception {
        when(request.getPathInfo()).thenReturn("/99");
        when(service.getById(99L))
            .thenThrow(new ContratoNotFoundException("99"));

        servlet.doGet(request, response);

        verify(response).setStatus(404);
    }
}
Patrón GIVEN-WHEN-THEN: Usa siempre esta estructura. GIVEN prepara el escenario (mocks, datos). WHEN ejecuta la acción. THEN verifica el resultado. Es tu plantilla universal para cualquier test.
Test del DAO contra BD real (H2 en memoria)
Objetivo: Verificar que las queries SQL y los mappings funcionan con una BD real. H2 en modo in-memory para velocidad. Testcontainers si necesitas MySQL/PostgreSQL exactos.
// ContratoDaoIntegrationTest.java

class ContratoDaoIntegrationTest {

    private static DataSource ds;
    private ContratoDao dao;

    @BeforeAll
    static void initDb() throws Exception {
        ds = new JdbcDataSource();
        ((JdbcDataSource) ds).setURL("jdbc:h2:mem:testdb;DB_CLOSE_DELAY=-1");
        // Ejecutar schema.sql para crear tablas
        try (Connection conn = ds.getConnection()) {
            ScriptUtils.executeSqlScript(conn,
                new File("src/main/resources/schema.sql"));
        }
    }

    @BeforeEach
    void setUp() {
        dao = new JdbcContratoDao(ds);
        // Limpiar datos entre tests
        dao.deleteAll();
    }

    @Test
    void save_yLuego_findById_retornaMismo() {
        Contrato nuevo = new Contrato(null, "CLT-001", "Activo");

        Contrato guardado = dao.save(nuevo);

        assertNotNull(guardado.getId());
        Contrato encontrado = dao.findById(guardado.getId());
        assertEquals("CLT-001", encontrado.getCodigo());
    }

    @Test
    void findAll_retornaListaOrdenada() {
        dao.save(new Contrato(null, "B-002", "Activo"));
        dao.save(new Contrato(null, "A-001", "Activo"));

        List<Contrato> todos = dao.findAll();

        assertEquals(2, todos.size());
        assertEquals("A-001", todos.get(0).getCodigo()); // Ordenado
    }
}
Test de integración completo — Servlet + Service + DAO
Embedded Tomcat: Arrancas un Tomcat embebido con tu Servlet real, BD H2 real, y llamas vía HTTP. Es el test más cercano a producción sin ser E2E.
// ContratoIntegrationTest.java — Tomcat embebido + BD real

class ContratoIntegrationTest {

    private static Tomcat tomcat;
    private static HttpClient client;
    private static String baseUrl;

    @BeforeAll
    static void startServer() throws Exception {
        tomcat = new Tomcat();
        tomcat.setPort(0); // Puerto aleatorio
        Context ctx = tomcat.addContext("", new File(".").getAbsolutePath());
        Tomcat.addServlet(ctx, "contratos", new ContratoServlet());
        ctx.addServletMappingDecoded("/api/contratos/*", "contratos");
        tomcat.start();
        baseUrl = "http://localhost:" + tomcat.getConnector().getLocalPort();
        client = HttpClient.newHttpClient();
    }

    @Test
    void crearYObtener_flujoCompleto() throws Exception {
        // POST — crear
        HttpRequest post = HttpRequest.newBuilder()
            .uri(URI.create(baseUrl + "/api/contratos"))
            .header("Content-Type", "application/json")
            .POST(BodyPublishers.ofString(
                "{\"codigo\":\"CLT-001\",\"estado\":\"Activo\"}"))
            .build();
        HttpResponse<String> postRes = client.send(post,
            BodyHandlers.ofString());
        assertEquals(201, postRes.statusCode());

        // GET — obtener
        HttpRequest get = HttpRequest.newBuilder()
            .uri(URI.create(baseUrl + "/api/contratos/1"))
            .GET().build();
        HttpResponse<String> getRes = client.send(get,
            BodyHandlers.ofString());
        assertEquals(200, getRes.statusCode());
        assertTrue(getRes.body().contains("CLT-001"));
    }

    @AfterAll
    static void stopServer() throws Exception {
        tomcat.stop();
    }
}
Contract testing — validar el contrato REST
¿Qué es? Verificar que el JSON que devuelve tu API tiene la estructura exacta que el frontend espera. Si cambias un campo en el backend, el contract test falla antes de que rompa la SPA.
Contrato del endpoint GET /api/contratos/{id}
Request
GET /api/contratos/1
Accept: application/json
→
Response 200
{ id, codigo, estado }
Content-Type: application/json
|
Response 404
{ error, message }
Contrato no encontrado
// ContratoApiContractTest.java — REST Assured

class ContratoApiContractTest {

    @Test
    void get_retornaEstructuraCorrecta() {
        given()
            .baseUri(BASE_URL)
            .accept(ContentType.JSON)
        .when()
            .get("/api/contratos/1")
        .then()
            .statusCode(200)
            .contentType(ContentType.JSON)
            .body("id", notNullValue())
            .body("codigo", matchesPattern("CLT-\\d{3}"))
            .body("estado", isOneOf("Activo", "Pendiente", "Cerrado"));
    }

    @Test
    void post_sinBody_retorna400() {
        given()
            .baseUri(BASE_URL)
            .contentType(ContentType.JSON)
            .body("{}")
        .when()
            .post("/api/contratos")
        .then()
            .statusCode(400)
            .body("error", equalTo("Validation failed"));
    }

    @Test
    void get_noExiste_retorna404ConMensaje() {
        given()
            .baseUri(BASE_URL)
        .when()
            .get("/api/contratos/99999")
        .then()
            .statusCode(404)
            .body("message", containsString("no encontrado"));
    }
}
Cuándo se rompe el contrato: Si renombras "codigo" a "code" en el backend, el contract test falla. Si el front espera "codigo" y recibe "code", la SPA se rompe. El contract test lo detecta antes del deploy.
Test de funciones JS puras — lógica sin DOM
Herramienta: Vitest (o Jest). Testea funciones que no tocan el DOM: validaciones, formateo, parseo, cálculos. Son los tests más rápidos y valiosos del front.
// contrato-utils.test.js — Vitest

import { describe, it, expect } from 'vitest';
import { validarCodigo, formatearEstado, calcularTotal } from './contrato-utils.js';

describe('validarCodigo', () => {
  it('acepta formato CLT-NNN', () => {
    expect(validarCodigo('CLT-001')).toBe(true);
    expect(validarCodigo('CLT-999')).toBe(true);
  });

  it('rechaza formatos inválidos', () => {
    expect(validarCodigo('')).toBe(false);
    expect(validarCodigo('ABC')).toBe(false);
    expect(validarCodigo(null)).toBe(false);
  });
});

describe('calcularTotal', () => {
  it('suma los importes de las líneas', () => {
    const lineas = [
      { concepto: 'Licencia', importe: 1000 },
      { concepto: 'Soporte', importe: 500 },
    ];
    expect(calcularTotal(lineas)).toBe(1500);

    expect(calcularTotal([])).toBe(0);
  });
});
Test de Fetch API — mockear llamadas al backend
MSW (Mock Service Worker) intercepta las llamadas HTTP del front sin tocar el backend real. Perfecto para testear que tu SPA llama al endpoint correcto con el body correcto.
// contrato-api.test.js — Vitest + MSW

import { http, HttpResponse } from 'msw';
import { setupServer } from 'msw/node';
import { getContrato, crearContrato } from './contrato-api.js';

// Mock server que intercepta fetch
const server = setupServer(
  http.get('/api/contratos/:id', ({ params }) => {
    if (params.id === '1') {
      return HttpResponse.json(
        { id: 1, codigo: 'CLT-001', estado: 'Activo' }
      );
    }
    return new HttpResponse(null, { status: 404 });
  }),
  http.post('/api/contratos', async ({ request }) => {
    const body = await request.json();
    return HttpResponse.json(
      { id: 2, ...body }, { status: 201 }
    );
  })
);

beforeAll(() => server.listen());
afterAll(() => server.close());

describe('getContrato', () => {
  it('retorna el contrato cuando existe', async () => {
    const c = await getContrato(1);
    expect(c.codigo).toBe('CLT-001');
    expect(c.estado).toBe('Activo');
  });

  it('lanza error cuando no existe', async () => {
    await expect(getContrato(99)).rejects.toThrow('404');
  });
});

describe('crearContrato', () => {
  it('envía POST y retorna con id', async () => {
    const nuevo = await crearContrato({
      codigo: 'CLT-002', estado: 'Pendiente'
    });
    expect(nuevo.id).toBeDefined();
    expect(nuevo.codigo).toBe('CLT-002');
  });
});

import { describe, it, expect, vi } from 'vitest';

describe('Formulario de contrato', () => {
  it('muestra error si código vacío al enviar', () => {

        <input id="codigo" value="" />

        <button type="submit">Guardar</button>
      </form>
    `;

    // Cargar el script que adjunta el listener
    require('./contrato-form.js');

    // WHEN — submit sin código
    document.getElementById('contrato-form').dispatchEvent(
      new Event('submit', { cancelable: true })
    );

    // THEN — muestra error

    expect(error.classList.contains('hidden')).toBe(false);
    expect(error.textContent).toContain('obligatorio');
  });
});
E2E con Cypress — el test definitivo
E2E = navegador real + servidor real + BD real. Es el test más lento pero el único que verifica que todo funciona junto. Testea solo los happy paths principales y los errores críticos. No dupliques lo que ya cubren los unit tests.
// cypress/e2e/contratos.cy.js

describe('Gestión de contratos', () => {

  beforeEach(() => {
    // Resetear BD a estado conocido antes de cada test
    cy.request('POST', '/api/test/reset-db');
    cy.visit('/');
  });

  it('crea un contrato y aparece en la lista', () => {
    // Navegar al formulario
    cy.get('[data-cy="btn-nuevo"]').click();

    // Rellenar formulario
    cy.get('#codigo').type('CLT-100');
    cy.get('#estado').select('Activo');
    cy.get('[data-cy="btn-guardar"]').click();

    // Verificar que aparece en la lista
    cy.get('[data-cy="tabla-contratos"]')
      .should('contain', 'CLT-100')
      .and('contain', 'Activo');

    // Verificar notificación de éxito
    cy.get('.toast-success')
      .should('be.visible')
      .and('contain', 'Contrato creado');
  });

  it('muestra error al crear con código duplicado', () => {
    // Crear primero
    cy.request('POST', '/api/contratos', {
      codigo: 'CLT-DUP', estado: 'Activo'
    });

    // Intentar crear duplicado desde la UI
    cy.get('[data-cy="btn-nuevo"]').click();
    cy.get('#codigo').type('CLT-DUP');
    cy.get('[data-cy="btn-guardar"]').click();

    // Verificar error
    cy.get('.toast-error')
      .should('contain', 'ya existe');
  });

  it('filtra contratos por estado', () => {
    cy.get('[data-cy="filtro-estado"]').select('Pendiente');

    cy.get('[data-cy="tabla-contratos"] tr').each(($row) => {
      cy.wrap($row).should('contain', 'Pendiente');
    });
  });
});
Buenas prácticas E2E:
• Usa data-cy="nombre" en el HTML para selectores estables (no dependen de CSS).
• Resetea la BD antes de cada test — los tests deben ser independientes.
• Solo 5-10 tests E2E para los flujos críticos. El resto se cubre con unit + integration.
• Nunca testees estilos CSS en E2E — eso es QA visual, no funcional.

Regla de oro del testing
1. Si es lógica de negocio → unit test con mock (ms)
2. Si toca BD o red → integration test con H2/Tomcat (100ms)
3. Si es el contrato JSON → contract test con REST Assured (200ms)
4. Si es un flujo de usuario completo → E2E con Cypress (5s)
5. Si ya lo cubre un nivel inferior → NO lo dupliques arriba
