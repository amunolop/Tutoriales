Servlet — GET /api/users
@WebServlet("/api/users")
public class UserServlet extends HttpServlet {
  private ObjectMapper mapper = new ObjectMapper();
  private List<User> users = new ArrayList<>();

  @Override
  protected void doGet(HttpServletRequest req,
                          HttpServletResponse res)
      throws IOException {
    // 1. Content-Type manual
    res.setContentType("application/json");
    // 2. Status code numerico
    res.setStatus(HttpServletResponse.SC_OK);
    // 3. Serializar manualmente
    String json = mapper.writeValueAsString(users);
    res.getWriter().write(json);
  }
}
Spring Boot — GET /api/users
@RestController
@RequestMapping("/api/users")
public class UserController {
  private final List<User> users = new ArrayList<>();

  @PostConstruct
  public void init() {
    users.add(new User(1L, "Juan", "juan@example.com"));
    users.add(new User(2L, "Maria", "maria@example.com"));
  }

  @GetMapping
  public ResponseEntity<List<User>> getAllUsers() {
    return ResponseEntity.ok(users);
  }
}
// Content-Type automatico  ok
// Status 200 implicito     ok
// JSON serializado solo    ok
Servlet — GET /api/users/{id}
@Override
protected void doGet(HttpServletRequest req,
                        HttpServletResponse res)
    throws IOException {
  String pathInfo = req.getPathInfo();
  res.setContentType("application/json");
  if (pathInfo == null || pathInfo.equals("/")) {
    res.setStatus(200);
    res.getWriter().write(mapper.writeValueAsString(users));
  } else {
    Long id = Long.parseLong(pathInfo.substring(1));
    users.stream()
      .filter(u -> u.getId().equals(id))
      .findFirst()
      .ifPresentOrElse(
        u -> {
          try {
            res.setStatus(200);
            res.getWriter().write(mapper.writeValueAsString(u));
          } catch (IOException e) {
            throw new RuntimeException(e);
          }
        },
        () -> res.setStatus(404)
      );
  }
}
Spring Boot — GET /api/users/{id}
@GetMapping("/{id}")
public ResponseEntity<?>
    getUserById(@PathVariable Long id) {
  return users.stream()
    .filter(u -> u.getId().equals(id))
    .findFirst()
    .map(ResponseEntity::ok)
    .orElseGet(() ->
      ResponseEntity
        .status(HttpStatus.NOT_FOUND)
        .build()
    );
}
// @PathVariable castea Long solo   ok
// 200 / 404 semanticos              ok
// Sin try/catch de IOException      ok
Servlet — POST /api/users
@Override
protected void doPost(HttpServletRequest req,
                         HttpServletResponse res)
    throws IOException {
  // 1. Leer body linea a linea
  StringBuilder sb = new StringBuilder();
  String line;
  BufferedReader reader = req.getReader();
  while ((line = reader.readLine()) != null) {
    sb.append(line);
  }
  // 2. Deserializar JSON manualmente
  User newUser = mapper.readValue(sb.toString(), User.class);
  // 3. Asignar ID manualmente
  newUser.setId((long) (users.size() + 1));
  users.add(newUser);
  // 4. Respuesta manual
  res.setContentType("application/json");
  res.setStatus(HttpServletResponse.SC_CREATED);
  res.getWriter().write(mapper.writeValueAsString(newUser));
}
Spring Boot — POST /api/users
@PostMapping
public ResponseEntity<User>
    createUser(@RequestBody User newUser) {
  // Spring deserializa el JSON automaticamente
  newUser.setId((long) (users.size() + 1));
  users.add(newUser);
  return ResponseEntity
    .status(HttpStatus.CREATED)
    .body(newUser);
}
// @RequestBody deserializa solo     ok
// Sin BufferedReader + while loop    ok
// Status 201 CREATED semantico      ok
Todo lo que debes hacer a mano con Servlets que Spring Boot resuelve automaticamente. Cada punto es codigo extra que tienes que escribir, mantener y en el que puedes cometer errores.

x

x
Serializar objetos a JSON en cada respuesta
mapper.writeValueAsString(obj)
x

Llamar a mapper.readValue() para convertir JSON a objeto Java

Usa Servlets cuando...

►Estas aprendiendo los fundamentos de HTTP y quieres ver que ocurre bajo el capo.
►Trabajas en una aplicacion legacy que ya usa Servlets y la migracion no esta justificada.
►Necesitas control absoluto y minima abstraccion sobre la request/response.
►El entorno tiene restricciones que impiden usar frameworks adicionales.
►Es un proyecto academico donde el objetivo es entender HTTP desde cero.

Usa Spring Boot cuando...

►Construyes una API REST para produccion: es el estandar de facto en la industria Java.
►Tu equipo necesita ser productivo rapidamente y el tiempo de desarrollo importa.
►Necesitas integracion con BD, seguridad, testing, metricas u otros servicios.
►El proyecto es un microservicio que se desplegara en contenedores (Docker/Kubernetes).
►Quieres codigo limpio, mantenible y que cualquier desarrollador Java pueda entender.
Servlet
+Control total sobre HTTP
+Sin magia, todo es explicito
+Ideal para entender los fundamentos
+Dependencias minimas
-Codigo verboso y repetitivo
-JSON manual y propenso a errores
-Sin inyeccion de dependencias
-Testing complejo con mocks pesados
-Raramente usado en proyectos nuevos
Spring Boot
+Codigo limpio y expresivo
+Serializacion JSON automatica
+Inyeccion de dependencias nativa
+Ecosistema enorme (Security, Data, Cloud...)
+Testing con MockMvc integrado
+Estandar absoluto en la industria
-Curva inicial por la autoconfiguracion
-Mayor consumo de memoria en arranque
-Excesivo para proyectos muy pequenos

Conclusion

Los Servlets son valiosos para entender los cimientos del desarrollo web en Java, pero Spring Boot es la eleccion correcta para cualquier proyecto real. La reduccion de boilerplate, la gestion automatica de JSON y HTTP, junto al ecosistema maduro, hacen que el ratio esfuerzo/resultado sea incomparable. Si ya dominas Servlets, la transicion a Spring Boot te resultara natural, y descubriras todo lo que hacian a mano que simplemente desaparece.
