¿Qué es Angular?

Framework Angular

Plataforma completa para crear SPAs (Single Page Applications). Incluye router, cliente HTTP, formularios, testing y CLI. Todo en un único paquete con TypeScript como lenguaje nativo.

Los cuatro pilares

Component
Component
Unidad mínima de UI. Encapsula template HTML, estilos CSS y lógica TypeScript. Tiene su propio ciclo de vida y puede comunicarse con el exterior vía @Input / @Output.
Service
Service + DI
Clase con lógica compartida (HTTP, estado, utilidades). Angular los crea una sola vez (singleton) y los inyecta donde se necesiten a través del sistema de Dependency Injection.
Module / Standalone
Módulos
Agrupan componentes, directivas y pipes relacionados. Desde Angular 14+ los Standalone Components eliminan la necesidad de NgModule para la mayoría de casos.
Directives & Pipes
Directives & Pipes
Las directives modifican el comportamiento del DOM (*ngIf, *ngFor, @if, @for). Los pipes transforman datos en el template (date, currency, async).

Change Detection

Default (Zone.js)
ChangeDetectionStrategy.Default
Zone.js intercepta todos los eventos asíncronos (clicks, timers, HTTP…) y dispara una comprobación en todo el árbol de componentes. Sencillo pero puede ser lento en apps grandes.
OnPush
ChangeDetectionStrategy.OnPush
El componente solo se re-renderiza si cambia una referencia en un @Input, se emite un evento, se ejecuta markForCheck() o se usa el pipe async. Mucho más performante.
Signals (v17+)
Signals
Sistema reactivo granular. Un Signal solo marca como "sucio" los componentes que lo leen. Permite apps completamente Zoneless — sin Zone.js — con cambios quirúrgicos en el DOM.
Pipe async
Pipe async
Suscribe automáticamente a un Observable o Promise en el template y llama a markForCheck() cuando llega un valor. Gestiona la desuscripción al destruir el componente — sin memory leaks.

@Component({
  selector: 'app-user-card',
  standalone: true,
  imports: [CommonModule, RouterLink],
  templateUrl: './user-card.component.html',
  changeDetection: ChangeDetectionStrategy.OnPush
})
export class UserCardComponent implements OnInit, OnDestroy {

  // Datos que recibe del padre
  @Input({ required: true }) user!: User;

  // Evento que emite al padre
  @Output() deleted = new EventEmitter<number>();

  // Servicio inyectado
  private userService = inject(UserService);

  ngOnInit(): void {
    console.log('Componente inicializado', this.user);
  }

  onDelete(): void {
    this.deleted.emit(this.user.id);
  }

  ngOnDestroy(): void {
    // Limpiar suscripciones aquí
  }
}

  // Signal writable
  count = signal(0);

  // Computed: se recalcula sólo cuando count cambia
  doubled = computed(() => this.count() * 2);

    console.log(`Count: `, this.count());

    this.count.update(v => v + 1);

  reset() {
    this.count.set(0);
  }

¿Qué es la Inyección de Dependencias?

Injector Dependency Injection (DI)

Angular mantiene un árbol de Injectors que sabe cómo crear instancias de servicios y las reutiliza (singleton). Tú declaras qué necesitas; Angular decide cómo crearlo.

🌍 Root Injector (ApplicationRef)
NgModule Injector (SharedModule)
AuthService (singleton)
HttpClient (singleton)
Component Injector (DashboardComponent)
DashboardService (instancia local)
Component Injector (WidgetComponent)
← hereda DashboardService del padre

Formas de registrar un servicio

providedIn: 'root'
Singleton global
La forma más común. Una sola instancia en toda la app. Tree-shaking si nadie lo usa.
@Injectable({ providedIn: 'root' })
providers: [ ] en Component
Instancia local
Nueva instancia por componente. Útil para servicios con estado local. Se destruye con el componente.
@Component({ providers: [MyService] })
useFactory / useValue
Proveedores avanzados
Usa una función fábrica para crear el servicio, o provee un valor concreto (configuración, tokens de env).
{ provide: TOKEN, useValue: config }

Código — Services e Interceptors

@Injectable({ providedIn: 'root' })
export class UserService {

  private http = inject(HttpClient);
  private apiUrl = '/api/users';

  // Devuelve Observable (lazy, no ejecuta hasta subscribe)
  getUsers(): Observable<User[]> {
    return this.http.get<User[]>(this.apiUrl);
  }

  getUserById(id: number): Observable<User> {
    return this.http.get<User>(`${this.apiUrl}/${id}`);
  }

  createUser(user: CreateUserDto): Observable<User> {
    return this.http.post<User>(this.apiUrl, user);
  }
}
// Forma moderna con inject() — sin constructor
@Component({ standalone: true })
export class ProductsComponent implements OnInit {

  private productService = inject(ProductService);
  private router = inject(Router);

  products: Product[] = [];

  ngOnInit() {
    this.productService.getAll()
      .subscribe(data => this.products = data);
  }
}

// Forma clásica con constructor
@Component({ /* ... */ })
export class OldStyleComponent {

  constructor(
    private productService: ProductService,
    private router: Router
  ) {}

// HTTP Interceptor: modifica todas las peticiones
export const authInterceptor: HttpInterceptorFn = (req, next) => {
  const token = inject(AuthService).getToken();

  if (token) {
    // Clona la request y añade el header
    const authReq = req.clone({
      headers: req.headers.set('Authorization', `Bearer ${token}`)
    });
    return next(authReq);
  }

  return next(req);
};

// Registro en main.ts o AppConfig
bootstrapApplication(AppComponent, {
  providers: [
    provideHttpClient(
      withInterceptors([authInterceptor])
    )
  ]
});

Angular Router

Router Navegación entre vistas

El Router de Angular mapea URLs a componentes, gestiona el historial del navegador y permite lazy loading por rutas para reducir el bundle inicial.

Guards — Protección de rutas

canActivate
¿Puede el usuario acceder?
Se ejecuta antes de activar una ruta. Si devuelve false o redirige, la navegación se cancela. Ideal para proteger rutas con autenticación.
canActivateChild
Rutas hijas
Como canActivate pero se aplica a todas las rutas hijas del segmento. Útil para módulos con sub-rutas que requieren autorización.
canDeactivate
canDeactivate
¿Puede salir?
Se ejecuta antes de abandonar una ruta. Perfecto para preguntar "¿descartar cambios?" cuando hay formularios sin guardar.
canMatch / canLoad
Lazy loading condicional
Decide si un módulo o ruta lazy se carga o no. Si falla, el chunk no se descarga. Más eficiente que canActivate para lazy routes.

Código de rutas

export const routes: Routes = [

  // Ruta pública
  { path: 'login', component: LoginComponent },

  // Ruta protegida con guard
  {
    path: 'dashboard',
    canActivate: [authGuard],
    component: DashboardComponent
  },

  // Lazy loading — sólo descarga el chunk cuando se accede
  {
    path: 'users',
    canActivate: [authGuard],
    canMatch: [roleGuard('ADMIN')],
    loadChildren: () =>
      import('./users/users.routes').then(m => m.USERS_ROUTES)
  },

  // Ruta con parámetros + resolver que pre-carga datos
  {
    path: 'users/:id',
    component: UserDetailComponent,
    resolve: { user: userResolver }
  },

  // Wildcard → 404
  { path: '**', component: NotFoundComponent }
];
// Guard funcional (Angular 15+)
export const authGuard: CanActivateFn = (route, state) => {
  const authService = inject(AuthService);
  const router = inject(Router);

  if (authService.isLoggedIn()) {
    return true;
  }

  // Redirige al login guardando la URL de retorno
  return router.createUrlTree(
    ['/login'],
    { queryParams: { returnUrl: state.url } }
  );
};

// Guard con rol — factory function
export const roleGuard = (role: string): CanMatchFn =>
  () => {
    return inject(AuthService).hasRole(role);
  };
// Resolver funcional — pre-carga datos antes de mostrar la vista
export const userResolver: ResolveFn<User> =
  (route, state) => {
    const id = +route.paramMap.get('id')!;
    return inject(UserService).getUserById(id);
  };

// En el componente, los datos resueltos están en:
// route.snapshot.data['user']

@Component({ standalone: true })
export class UserDetailComponent implements OnInit {
  private route = inject(ActivatedRoute);

  user!: User;

  ngOnInit() {
    this.user = this.route.snapshot.data['user'];
  }
}

RxJS — Programación Reactiva

RxJS Observables y operadores

RxJS permite modelar cualquier flujo asíncrono (HTTP, eventos, timers) como un stream de valores. Los operadores transforman, filtran y combinan estos streams de forma declarativa.

Flujo Observable
Observable
http.get()
→
Operadores
map, filter, switchMap
→
Subscribe
next / error / complete
→
Unsubscribe
destroy / takeUntil

Operadores más usados

switchMap
Cancelar previo
Cancela la suscripción anterior y empieza con la nueva. Perfecto para búsquedas en tiempo real — cancela la petición HTTP si el usuario sigue escribiendo.
mergeMap
Paralelo
Ejecuta los inner Observables en paralelo y mezcla sus resultados. Útil para peticiones independientes que no necesitan cancelarse.
combineLatest
Combinar streams
Emite cada vez que cualquiera de los Observables fuente emite un valor, combinando los últimos valores de todos ellos.
debounceTime
Anti-rebote
Solo emite un valor si han pasado N milisegundos sin que el source haya emitido otro. Indispensable para inputs de búsqueda.
takeUntilDestroyed
Auto-cancelar
Cancela la suscripción automáticamente cuando el componente se destruye. La forma más limpia de evitar memory leaks en Angular 16+.
BehaviorSubject
Estado reactivo
Subject que recuerda el último valor emitido. Ideal para almacenar estado en un Service. Los nuevos suscriptores reciben el valor actual al momento de suscribirse.

Código

// Búsqueda reactiva — patrón clásico con RxJS
@Component({ standalone: true, imports: [ReactiveFormsModule, AsyncPipe] })
export class SearchComponent {
  searchControl = new FormControl('');
  private productService = inject(ProductService);

  results$ = this.searchControl.valueChanges.pipe(
    debounceTime(300),       // espera 300ms tras el último keystroke
    distinctUntilChanged(), // no emite si el valor no cambió
    filter(q => q.length >= 2),
    switchMap(q =>          // cancela la petición anterior
      this.productService.search(q).pipe(
        catchError(() => of([]))  // maneja errores
      )
    )
  );
}
// En el template: {{ results$ | async }}
// Gestión de estado con BehaviorSubject en un Service
@Injectable({ providedIn: 'root' })
export class CartService {

  private items$ = new BehaviorSubject<CartItem[]>([]);

  // Solo exponemos el Observable (readonly)
  readonly cart$ = this.items$.asObservable();
  readonly total$ = this.cart$.pipe(
    map(items => items.reduce((sum, i) => sum + i.price * i.qty, 0))
  );

  addItem(item: CartItem): void {
    const current = this.items$.getValue();
    this.items$.next([...current, item]);
  }

  clear(): void {
    this.items$.next([]);
  }
}
// Mismo carrito pero con Signals (Angular 17+)
@Injectable({ providedIn: 'root' })
export class CartSignalService {

  // Signal es writable internamente
  private _items = signal<CartItem[]>([]);

  // Exponemos como ReadonlySignal
  readonly items = this._items.asReadonly();

  // computed() es equivalente a derivedState
  readonly total = computed(() =>
    this._items().reduce((sum, i) => sum + i.price * i.qty, 0)
  );
  readonly count = computed(() => this._items().length);

  addItem(item: CartItem): void {
    this._items.update(curr => [...curr, item]);
  }
}

// En template NO necesita | async, es sincrónico:
// {{ total() }} — directo, sin subscribe

Ciclo de vida de un Componente

Lifecycle Hooks Desde creación hasta destrucción

Angular llama a estos métodos en orden predefinido. Implementar la interfaz correspondiente es opcional pero recomendable para autocompletar.

01 constructor Instanciación. Inyectar dependencias. NO hay @Input disponible aún.
02 ngOnChanges Primer cambio en @Input. Se repite cada vez que cambia un @Input.
03 ngOnInit Inicialización. @Inputs ya disponibles. Ideal para llamadas HTTP iniciales.
04 ngDoCheck Detección manual de cambios. Úsalo con cuidado — se ejecuta muy frecuentemente.
05 ngAfterViewInit El template y sus hijos están en el DOM. Acceso a @ViewChild disponible.
06 ngOnDestroy Antes de eliminar del DOM. Cancelar suscripciones, limpiar timers, evitar memory leaks.

¿Cuándo usar cada hook?

ngOnInit ← el más usado
Llamadas HTTP, suscripciones a Observables, leer parámetros de ruta, inicializar formularios reactivos. Cualquier lógica de inicio que necesite los @Inputs.
ngOnChanges
Reaccionar a cambios concretos en @Inputs. Recibe un objeto SimpleChanges con el valor anterior y el nuevo. Útil para componentes "tontos" que procesan los datos recibidos.
ngAfterViewInit
Acceder a elementos del DOM vía @ViewChild / @ViewChildren, integrar librerías de terceros (charts, mapas), medir dimensiones del DOM tras el primer renderizado.
ngOnDestroy ← siempre limpiar
Llamar a subject.complete(), cancelar intervalos con clearInterval, desconectarse de WebSockets. Sin esto aparecen memory leaks que ralentizan la app.

Código

@Component({ standalone: true, selector: 'app-demo', template: '...' })
export class DemoComponent
  implements OnChanges, OnInit, AfterViewInit, OnDestroy {

  @Input() userId!: number;
  @ViewChild('chartCanvas') canvas!: ElementRef;

  private destroyRef = inject(DestroyRef);
  private userService = inject(UserService);

  user: User | null = null;

  ngOnChanges(changes: SimpleChanges): void {
    if (changes['userId'] && !changes['userId'].firstChange) {
      // userId cambió — recargar datos
      this.loadUser();
    }
  }

  ngOnInit(): void {
    this.loadUser(); // primera carga
  }

  ngAfterViewInit(): void {
    // DOM listo, podemos acceder al canvas
    console.log(this.canvas.nativeElement);
  }

  ngOnDestroy(): void {
    // DestroyRef cancela automáticamente las subs
  }

  private loadUser(): void {
    this.userService.getUserById(this.userId)
      .pipe(takeUntilDestroyed(this.destroyRef))
      .subscribe(u => this.user = u);
  }
}
// Patrón 1: takeUntilDestroyed (Angular 16+) — RECOMENDADO
export class ModernComponent {
  private destroyRef = inject(DestroyRef);

  ngOnInit() {
    interval(1000)
      .pipe(takeUntilDestroyed(this.destroyRef))
      .subscribe(n => console.log(n));
  }
}

// Patrón 2: Subject + takeUntil — clásico
export class ClassicComponent implements OnDestroy {
  private destroy$ = new Subject<void>();

  ngOnInit() {
    interval(1000)
      .pipe(takeUntil(this.destroy$))
      .subscribe(n => console.log(n));
  }

  ngOnDestroy() {
    this.destroy$.next();
    this.destroy$.complete();
  }
}

// Patrón 3: Signals — sin suscripciones manuales
export class SignalComponent {
  count = signal(0);

  ngOnInit() {
    // No hay suscripción — signals no necesitan unsubscribe
    setInterval(() => this.count.update(n => n + 1), 1000);
  }
}
