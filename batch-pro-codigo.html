SPRING BATCH ENGINEERING

Diseño de Motor Genérico: Chunk 50 | Retry 2 | Skip 2 | Watchman

1 Estrategia de Tolerancia a Fallos

Chunk-Oriented

Procesamiento en bloques de 50. Transaccionalidad atómica para asegurar rendimiento y consistencia.

Retry-Logic

Si falla, reintenta hasta 2 veces. Ideal para micro-cortes de red o Deadlocks de base de datos.

Skip & Audit

Tras fallar el reintento, se "salta" el registro y se guarda en la tabla de auditoría para el Watchman.

2 Implementación Java (Spring Boot)

A. Configuración del Step

@Bean
public Step resilientStep(JobRepository jobRepository, PlatformTransactionManager tm) {
    return new StepBuilder("resilientStep", jobRepository)
        .<Input, Output>chunk(50, tm)
        .reader(itemReader())
        .writer(itemWriter())
        .faultTolerant() // Activa gestión de errores
        .retry(Exception.class).retryLimit(2)
        .skip(Exception.class).skipLimit(2)
        .listener(auditSkipListener())
        .build();
}

B. Listener de Auditoría (El Fotógrafo)

@Component
public class AuditSkipListener implements SkipListener<Object, Object> {
    private final JdbcTemplate jdbcTemplate;

    public void onSkipInWrite(Object item, Throwable t) {
        String sql = "INSERT INTO BATCH_ERROR_LOG (data_raw, error_msg) VALUES (?, ?)";
        jdbcTemplate.update(sql, item.toString(), t.getMessage());
    }
}
