🦞 Concepto¿Qué es OpenClaw?

OpenClaw es un agente de IA autónomo y open-source que corre en tu propia máquina. A diferencia de ChatGPT o Claude (que solo conversan), OpenClaw tiene "ojos y manos": puede navegar la web, leer/escribir ficheros, ejecutar comandos, enviar mensajes y automatizar workflows. Es como tener un compañero de trabajo digital 24/7 que se comunica contigo por WhatsApp, Telegram o Slack.

Chatbot vs Agente — la diferencia clave
Chatbot (ChatGPT, Claude.ai):
• Solo conversa — genera texto
• No puede tocar tu sistema
• Pierde contexto entre sesiones
• Tú haces el trabajo, él aconseja
• Vive en la nube del proveedor
Agente (OpenClaw):
• Conversa y ejecuta acciones
• Lee/escribe ficheros, ejecuta shell
• Memoria persistente 24/7
• Él hace el trabajo, tú supervisas
• Vive en tu máquina (privacidad)

Ficheros del workspace
El workspace es una carpeta con ficheros Markdown que definen quién eres, cómo es tu agente y qué recuerda.
FicheroQué contiene
SOUL.mdPersonalidad del agente: tono, estilo, reglas de comportamiento. Es el "system prompt" editable.
USER.mdInfo sobre ti: nombre, preferencias, zona horaria, contexto profesional.

Instalación rápida
Requisitos: Node.js 22+, una API key de un LLM (Claude recomendado), y una máquina que se quede encendida (tu portátil, un Mac Mini, Raspberry Pi, o VM cloud).
macOS / Linux
Instalación en un comando
El script instala Node.js, Python y el CLI de OpenClaw.
# Instalar OpenClaw
curl -fsSL https://get.openclaw.ai | bash

# Crear workspace
openclaw init

# Configurar modelo y API key
openclaw config

# Arrancar el gateway
openclaw gateway start

Skills vs Tools — no los confundas
Tool = una función que el agente puede invocar: exec (shell), browser, web_search, fs (files), message. Son los permisos reales. Sin el tool exec, el agente no puede ejecutar nada aunque tenga un skill que lo instruya.
Skill = un fichero Markdown (SKILL.md) que se inyecta en el system prompt. Le dice al agente cómo hacer algo: "cuando te pidan notas de Obsidian, busca en ~/vault/". Un skill es un manual, no un permiso.
Regla de los 3 requisitos: Para que un skill funcione necesitas: 1) Config: ¿está el tool habilitado? 2) Instalación: ¿está la herramienta instalada en la máquina? 3) Autorización: ¿tienes credenciales? Si falla cualquiera de los 3, el skill no hace nada.
Crear tu propio skill
# 1. Crear carpeta del skill
mkdir -p ~/.openclaw/skills/deploy-checker
cd ~/.openclaw/skills/deploy-checker

# 2. Crear SKILL.md
cat > SKILL.md << 'EOF'
---
name: deploy-checker
description: Check deployment status and health of our Java services on staging and production.
metadata:
  openclaw:
    emoji: "🚀"
    requires:
      bins: ["curl"]
---

# Deploy Checker

When the user asks about deployment status, health checks, or service availability:

1. Use `curl` to hit the health endpoint:
   - Staging: `https://staging.myapp.com/actuator/health`
   - Production: `https://prod.myapp.com/actuator/health`

2. Parse the JSON response and report:
   - Status (UP/DOWN)
   - Database connection
   - Disk space
   - Last deploy timestamp from `/actuator/info`

3. If any service is DOWN, immediately alert with details.

Always report in a clear table format.
EOF

# 3. Reiniciar gateway para que lo cargue
openclaw gateway restart

# 4. Verificar que se registró
openclaw skills list --eligible

⚠️ Riesgos reales
OpenClaw es potente Y potencialmente peligroso. Tiene acceso a tu sistema: ficheros, shell, email, navegador. Una mala configuración puede exponer datos sensibles. Trata OpenClaw como tratarías dar acceso root a un becario muy inteligente pero impredecible.
RiesgoDescripciónMitigación
Prompt injectionUn email o web maliciosa inyecta instrucciones al agenteLimitar tools con tools.allow/deny. No dar acceso a email sin filtros.
Skills maliciososSkills de terceros en ClawHub pueden contener código peligrosoLeer SIEMPRE el SKILL.md antes de instalar. Preferir skills oficiales.
Exposición gatewaySi expones el puerto 18789 a internet sin authUsar Tailscale para acceso remoto. Nunca exponer sin autenticación.
Credenciales en configAPI keys en openclaw.json en texto planoUsar variables de entorno o secret managers.
Acciones destructivasEl agente puede borrar ficheros, emails, etc.Activar tools.exec.ask: true para pedir confirmación antes de ejecutar.
Config de seguridad recomendada
// openclaw.json — config segura para empezar
{
  "tools": {
    "allow": ["group:fs", "browser", "web_search", "message"],
    "deny": ["exec"],           // Shell deshabilitado al inicio
    "exec": {
      "ask": true,              // Pide confirmación antes de ejecutar
      "security": "sandboxed"  // Modo sandbox
    }
  },
  "skills": {
    "allowBundled": [          // Solo skills oficiales
      "summarize",
      "humanizer",
      "session-logs"
    ]
  }
}
Regla de mínimo privilegio: Empieza con todo denegado. Habilita tools y skills uno a uno según los necesites. openclaw doctor te avisa de configs inseguras.
🔒
Checklist de seguridad antes de usar
1. Ejecuta openclaw doctor y resuelve todos los warnings
2. No expongas el gateway a internet sin Tailscale o VPN
3. Lee CADA skill antes de instalarlo — son código ejecutable
4. Activa tools.exec.ask: true hasta que confíes en el agente
5. No pongas API keys directamente en openclaw.json — usa env vars
6. Haz backups de tu workspace (MEMORY.md, SOUL.md) periódicamente
