RAG
Retrieval Augmented Generation

Patrón arquitectónico que combina búsqueda de información con generación de texto. En lugar de que el LLM responda solo con lo que "memorizó" en su entrenamiento, primero buscamos documentos relevantes y se los damos como contexto.

No hallucinations Conocimiento actualizable Respuestas fundamentadas
🔢
Embedding
Representación vectorial semántica

Función que convierte un texto en un array de números flotantes (vector) que captura su significado semántico. Textos similares → vectores cercanos en el espacio n-dimensional.

text-embedding-3-small 1536 dimensiones cosine similarity
🗄️
BBDD Vectorial
Vector Store / Index

Base de datos optimizada para búsqueda por similitud de vectores (ANN — Approximate Nearest Neighbor). Almacena embeddings y devuelve los K más cercanos al vector query en milisegundos.

Pinecone pgvector Chroma Weaviate
🤖
LLM
Large Language Model

Modelo de lenguaje que recibe un prompt con contexto + pregunta y genera una respuesta coherente. En RAG, el contexto son los fragmentos recuperados de la BBDD vectorial.

GPT-4o Claude 3.5 Llama 3 Gemini

¿Por qué RAG?

Los LLMs tienen un knowledge cutoff y no conocen tus documentos internos. RAG resuelve esto sin necesidad de reentrenar el modelo: buscas los fragmentos relevantes de tu base documental y se los inyectas al LLM como contexto, obteniendo respuestas precisas, actualizadas y trazables.

① FASE DE INDEXACIÓN — se hace una sola vez (o cuando hay nuevos documentos)
PASO 1
📄 Documentos fuente
PDFs, markdowns, páginas web, FAQs, base de conocimiento interna...
PASO 2
✂️ Chunking
Se divide el texto en fragmentos de ~512 tokens con solapamiento para no perder contexto entre chunks.
PASO 3
🔢 Embedding
Cada chunk pasa por el modelo de embedding → vector de 1536 números que representa su significado.
PASO 4
🗄️ Almacenar
Vector + texto original + metadata se guardan en la BBDD vectorial, indexados para búsqueda rápida.
② FASE DE CONSULTA — ocurre en cada pregunta del usuario
PASO 1
💬 Pregunta usuario
"¿Cuál es la política de devoluciones para productos digitales?"
PASO 2
🔢 Embed query
La pregunta se convierte en un vector con el mismo modelo de embedding que se usó en la indexación.
PASO 3
🔍 Similarity search
Se buscan los Top-K chunks cuyo vector es más similar (cosine similarity) al vector de la pregunta.
PASO 4
🤖 Llamada LLM
Se construye el prompt: [sistema] + [contexto recuperado] + [pregunta]. El LLM responde fundamentado en los chunks.
SALIDA
✅ Respuesta
Respuesta precisa, basada en documentos reales, con posibilidad de incluir fuentes/citas.
🔢
¿Qué es un embedding?

Un modelo de embedding es una red neuronal entrenada para proyectar cualquier texto en un espacio vectorial de alta dimensión (ej. 1536D). La clave es que la distancia entre vectores refleja la similitud semántica: "gato" y "felino" estarán cerca; "gato" y "factura" estarán lejos.

Texto original
"Los productos digitales no admiten devolución"
↓ embedding model
Vector resultante (simplificado)
0.0231-0.18420.00930.5671-0.21300.08840.3312-0.00410.19230.0782... [1536 valores]
Aspecto Descripción Ejemplo / Valor
Dimensiones Número de valores en el vector. Más dimensiones = más capacidad semántica. 768 / 1536 / 3072
Similitud Cómo se mide la cercanía entre dos vectores. Cosine similarity es el más usado en RAG. cosine · dot product · euclidean
Modelos populares Modelos especializados en embeddings, distintos al LLM generativo. text-embedding-3-small · nomic-embed
Normalización Los vectores se normalizan a longitud 1 para que cosine similarity = dot product. ‖v‖ = 1
Chunking previo El texto se divide antes de embedear. Tamaño de chunk afecta la calidad del retrieval. ~512 tokens, overlap 50
🗄️
¿Qué almacena?
Vector — el embedding del chunk (array float de 1536 valores)
Texto original — el chunk de texto para poder enviarlo al LLM
Metadata — fuente, fecha, sección, página, autor...
ID único — para poder actualizar o borrar un documento
⚡
¿Cómo busca?
ANN — Approximate Nearest Neighbor: no compara con todos, usa índices inteligentes (HNSW, IVF)
Top-K — devuelve los K chunks con mayor similitud (ej. K=4)
Score threshold — filtra resultados con similitud mínima para evitar ruido
Metadata filter — combina búsqueda vectorial con filtros tradicionales (ej. by_date, by_source)

Cómo se construye el prompt en RAG

El LLM no "sabe" nada del proceso RAG. Solo recibe un prompt con el contexto ya inyectado. La app es responsable de construir ese prompt correctamente.

[SYSTEM]
Eres un asistente de soporte. Responde SOLO usando el contexto proporcionado.
[CONTEXTO RECUPERADO — Top-K chunks]
Chunk 1 (score: 0.92): "Los productos digitales, incluyendo software y licencias, no son elegibles para devolución una vez activados..."
Chunk 2 (score: 0.87): "El plazo para solicitar devolución en productos físicos es de 14 días naturales desde la recepción..."
[PREGUNTA USUARIO]
¿Puedo devolver un producto digital que compré ayer?
Parámetro LLMQué controlaRecomendación en RAG
temperature Aleatoriedad de la respuesta. 0 = determinista, 1 = creativo. 0.0 – 0.2 — baja para respuestas factuales precisas
max_tokens Longitud máxima de la respuesta generada. 512 – 1024 — suficiente para respuestas de soporte
context window Límite total de tokens (prompt + respuesta). Determina cuántos chunks caben. GPT-4o: 128K · Claude: 200K → caben muchos chunks
system prompt Instrucciones persistentes: rol, restricciones, formato de respuesta. Indica que responda solo con el contexto dado; cita fuentes
streaming Devolver tokens según se generan (Server-Sent Events). true — mejora la percepción de velocidad en el UI
